# 校园智能体（桌面端）

自己写的 Electron 壳加自己的界面包，引擎用 DeepSeek Harness（`@deepseek-ai/dsh`，锁在 0.2.0-rc.2，不改它的代码）。产品名和图标是占位的。

## 目录

| 位置 | 内容 |
|---|---|
| `desktop/` | 桌面端的壳：`main.cjs` 开窗口、管进程；`preload.cjs` 让界面顶到窗口边缘；`host.mjs` 启动引擎 |
| `ui/` | 界面包：`client/` 是浏览器侧源码，`host.js` 是引擎侧入口，`lib/` 是构建产物 |
| `core/zju/` | ZJU Core：校园系统的命令和技能说明。从 ZJU Skill 复制过来单独改，不再连原来的文件夹 |
| `core/learn/` | Learning Core：把资料讲成带画面的讲解。从 Learning 技能复制过来单独改 |
| `core/AGENT.md` | 助手的底层说明：每次对话都放进系统提示的那一篇（见「助手的底层说明」） |
| `core/weread/` | WeRead Core：从本机微信或微信读书找公众号文章，读正文、存成 Markdown。从 WeRead Skill 复制过来单独改（见「微信公众号」） |
| `app.patch.yml` | 组合层：关掉引擎的哪些部分、换人设、插入我们的包 |
| `计划/` | 计划、盘点和探测脚本 |
| `比赛/` | 比赛要求、申报书、承诺书 |

## 命令

```bash
npm start
```

一条命令打开应用，也可以直接双击 `start.cmd`。它会构建界面包、启动窗口，并在窗口开着时监听 `ui/client/`：改完代码约一秒生效，不用重启。改 `desktop/`、`app.patch.yml` 或引擎侧的 `ui/profile/*.mjs` 需要关掉重开；没重开时界面是新的、后台是旧的，这时页面上的请求一出错就会改成提示「请完全退出应用再打开」。做法是界面包每次构建时记下引擎侧代码的指纹，引擎启动时也算一份，页面拿两份比（`ui/profile/stamp.mjs`、`ui/client/api.ts`）。同一份数据目录只会开一个：已经开着时再开一次，是把原来的窗口叫到前面，新开的那个自己退出。

```bash
npm run typecheck
```

```bash
npm run typecheck:core
```

前一条查界面包，后一条查 `core/zju`（它有自己的 TypeScript 和依赖，在 `core/zju/node_modules`）。

```bash
npm run package
```

打出 `dist/win-unpacked/CampusAgent.exe`（未签名，约 870 MB），只是一个文件夹。

```bash
npm run installer
```

打出发布用的安装程序 `dist/CampusAgent-Setup-<版本>.exe`（未签名，约 310 MB）。双击就装，不问路径，装在 `%LOCALAPPDATA%\Programs\campus-agent`；卸载不删 `%APPDATA%\CampusAgent` 里的数据。装新版本会先把旧版本的安装目录整个换掉，所以应用自己不往安装目录里写东西。

**安装程序为什么改成了 zip。** 0.1.2 及以前的安装程序装得很慢（用户 2026-10-11 说的）。原因是文件多加上 electron-builder 的装法：成品有 19,494 个文件（1.4 万个不到 4 KB，绝大多数在 `node_modules` 里），而它默认的装法是先把压缩包整个解到临时目录，再用系统的复制把每个文件拷进安装目录，最后删掉临时的那一份（`app-builder-lib/templates/nsis/include/extractAppPackage.nsh` 的 `extractUsing7za`）；升级时旧版本的卸载程序还要先把旧文件一个一个挪走。拿 0.1.2 的安装包在开发机上（NVMe，没开杀毒）把这几步拆开量过：解到临时目录 19 秒，复制进安装目录 93 秒，删临时目录 3 秒。开着杀毒的普通笔记本上每一步都要再慢几倍。改了三处：

- `package.json` 的 `build.nsis` 加了 `useZip` 和 `differentialPackage: false`：应用打成 zip，安装时直接解进安装目录，每个文件只写一次。代价是安装程序从 244 MB 变成 316 MB（zip 压得不如 7z），以及没有 `.blockmap`、更新时不能只下变了的部分（本来也是整个下的，`desktop/update.cjs` 里把这种下法关掉了）。
- `scripts/after-pack.cjs` 多了一步 `dropDeadWeight`：删掉各个 `node_modules` 里的源码映射（`.map`）和类型声明（`.d.ts` 等），运行时没有东西读它们。5,680 个文件、48 MB，成品剩 13,816 个文件。说明文档没删（引擎有的页面会读包里的说明）；我们自己的代码和 `core` 里的不动。
- 解 zip 的组件（nsisunz）写不了名字带中文的文件：装到 `core/learn/朗读器.cmd` 就弹「Failed to decompress files」停住，后面的都没装上（第一次试装就是这样）。这个文件是配音朗读器的启动脚本，应用里用不上，在 `build.files` 里排除了；`after-pack.cjs` 另加了一道检查（`oddNames`），成品里再出现名字带非 ASCII 字符的文件，打包直接失败并指出是哪个。**以后往 `core/` 里放文件，名字用英文。**

验证：打了一个改了名字和标识的测试包（装在 `campus-agent-installtest`，和正式的互不相干），在开发机上真装：全新安装 16.5 秒（原来的装法拆开量是 115 秒左右）；装在已有的上面（升级走的路）36.8 秒；装好的应用用单独的数据目录启动，引擎起来了、网页服务有回应；卸载后文件夹、注册表项、快捷方式都没有留下。0.1.3 发版前照这个办法又装了一次（16.6 秒），启动时把 PATH 里的 Node.js 拿掉：应用在数据目录里放好了 `node.cmd`，在没有 Node.js 的命令行里用它跑装好的 `core/zju/scripts/zju.ts` 和 `core/learn/engine/build.mjs`，都跑起来了（见「给命令行用的 Node」）。没验证的：开着杀毒的普通笔记本上要多久；从 0.1.2 用应用自己的更新升上来（第一次升级还要等旧版本的卸载程序把 19,494 个旧文件挪走）；装好的应用里各个功能逐个走一遍（只看了引擎能起来）。

还能再快的一条路没有走：打成 asar（成品从一万多个文件变成一两千个，7z 也能用回来）。它要把 `core/`、带可执行文件和原生模块的包留在外面，引擎从 asar 里加载、各处启动子进程的写法都要在装好的应用里重新验一遍，风险比上面三处大得多，留到以后。

两条命令打完都会多走一步 `scripts/after-pack.cjs`（补依赖；补完再删掉用不到的文件、查有没有名字带中文的文件，见下面「安装程序为什么改成了 zip」）：electron-builder 只沿着 `dependencies` 收集要带的包，引擎的包之间却大量用 `peerDependencies` 互相引用，不补的话成品里会缺二十多个引擎的包。**试打包成品要在项目目录以外试**（装上，或者把 `win-unpacked` 拷到别处）：在 `dist` 里直接运行时，Node 会一层层往上找到项目自己的 `node_modules`，缺了包也照样能启动，看不出问题。0.1.0 的便携包就是这样带着缺口发出去的，在别的位置起不来。

## 数据放在哪

应用自己的会话和设置在 `%APPDATA%\CampusAgent\`，和本机装的 DeepSeek Harness 的 `~\.dsh` 分开。

API Key 统一放在一个文件 **`api-keys.local.yaml`** 里。开发时它在项目根目录（`D:\Innovation\api-keys.local.yaml`），直接修改 `refs` 下的 `DEEPSEEK_API_KEY` 即可；装好的应用里它在数据目录（`%APPDATA%\CampusAgent\api-keys.local.yaml`），升级不会丢。对话和网页搜索共用它。应用设置里的 Key 输入框也写回这一份文件，保存后对后续请求生效，直接编辑文件同样会自动加载。放哪由壳决定（`desktop/main.cjs` 的 `keysDir`），经 `CAMPUS_KEYS_DIR` 告诉引擎，微信公众号插件认验证码用的也是这一份里的 Key。

`DEEPSEEK_API_KEY` 在这里仅是文件字段名。启动不再读取同名环境变量、不加载 `.env`，也不从 `~\.dsh` 或旧的应用凭据文件自动复制密钥。首次配置可以照 `api-keys.example.yaml` 填写，或直接在界面输入保存；文件不存在时不会沿用旧 Key。

本地密钥文件已加入 `.gitignore`，打包只包含示例。0.1.0 的便携包把它写在解压目录的 `resources/app/` 里，从那一版换过来要重新填一次 Key。

引擎默认把完整会话日志随请求额外上传给 DeepSeek，`app.patch.yml` 里关掉了。

## 用 ChatGPT 账号登录

设置 → 模型页最下面有一块「ChatGPT」。登录后模型选择器里多出 GPT，和 DeepSeek 并列，随时切换；新对话默认用 GPT-6.1 Sol、推理强度 Xhigh（已经开着的对话各用各的，不变）。退出登录后 GPT 从选择器里消失，默认模型改回引擎原来的 DeepSeek；登录期间自己把默认模型换成了别的，退出时不动它。两种登录方式：

- 「登录」：在系统浏览器里打开 OpenAI 的登录页，登完浏览器跳回本机（`localhost:1455`），应用自己变成已登录。浏览器没能跳回来时，把它地址栏里的地址贴进卡片里的输入框。
- 「用代码登录」：卡片上显示一段代码，在 OpenAI 的验证页里输入。浏览器和应用不在同一台机器、或者 1455 端口被占时用这个。

登录、令牌的保存和刷新、发请求都是引擎自带的（`@deepseek-ai/dsh-llm-pi-ai` 的 `openai-codex` 线路，底下是 pi-ai）：用的是 OpenAI 的 OAuth，和 Codex 客户端同一套；请求走 Responses 协议，发到 `chatgpt.com/backend-api`，算在 ChatGPT 订阅里（pi-ai 标的是 Plus / Pro），不需要 API Key。引擎的模型页只给这条线路留了填 API Key 的输入框，没有登录入口，我们补的是：

- `ui/profile/chatgpt.mjs`：替页面发起、取消登录，把要人去的页面、要输入的代码、要贴回来的地址转给页面；登录成功后把线路写进模型设置（引擎的 `llm-pi-ai` 配置里的 `providers.openai-codex`），再把新对话的默认模型写进 `agent-default-model`；退出时把默认模型改回去、撤掉线路、删掉令牌。
- `ui/client/ChatGptCard.tsx`：那一块卡片，登记在引擎留的 `settings.models.footer` 上。
- `desktop/main.cjs`：`auth.openai.com` 的页面交给系统浏览器开，不进应用自己的阅读窗口。

令牌和 DeepSeek 的 Key 存在同一个文件里（`api-keys.local.yaml` 的 `records` 下面的 `llm-pi-ai/openai-codex`），这个文件不要发给别人。退出登录只在本机删掉令牌，不通知 OpenAI。

有哪些模型、各有哪几档推理强度，取自 pi-ai 自带的模型表（现在是 0.87.1 的八个：GPT-5.3 Codex Spark、GPT-5.5、GPT-5.6 Luna / Sol / Terra、GPT-6 Astra / Luna / Sol），不是向账号查的：表里有而账号用不了的模型，要到发消息时才报错。GPT-6.1 Sol 比这张表新，是照 pi-ai 1.1.0 的模型表抄进 `chatgpt.mjs` 的 `NEWER_MODELS` 补上的（名字、上下文长度、输出上限、能看图、推理档位）；引擎自带的 pi-ai 不认识它，所以它没有自带模型那几项按模型开的协议开关，只走这条线路通用的发法。默认模型选的就是它，改默认模型改 `chatgpt.mjs` 的 `DEFAULT`。表里有的档位只是别的档位的别名（`minimal` 发出去就是 `low`），写线路时去掉了，所以选择器里每一档发出去的值都不一样：GPT-5.5 是 Off、Low、Medium、High、Xhigh，GPT-6.1 Sol 是 Low、Medium、High、Xhigh、Max。引擎升级带来新的模型表后，重新登录一次线路才会按新表重写。

验证过的：在真实引擎上发起浏览器登录（拿到 OpenAI 的授权地址，带 PKCE）和代码登录（OpenAI 发回了代码）、取消、登录成功后那一步对模型设置和默认模型的写入、退出时的撤销和默认模型改回、选择器里 GPT-5.5 和 GPT-6.1 Sol 的档位、新对话默认显示 GPT-6.1 Sol / Xhigh、登录页由系统浏览器打开。**没有验证的：真的登完一个账号，以及登录后发一条消息**（GPT-6.1 Sol 是补进去的，尤其要试），这两步要有 ChatGPT 账号的人在应用里做一遍。引擎进程自己访问 `auth.openai.com` 和 `chatgpt.com`，本机要连得上。

## 对话和它的文件夹

新会话默认不用选工作区，做法照 Codex：聊天记录在应用数据目录（`%APPDATA%\CampusAgent\home`），每个对话另有一个自己的文件夹 `文档\CampusAgent\<日期>\<时分>`，对话里产生的文件落在里面。文件夹由 `ui/profile/chats.mjs` 建；环境变量 `CAMPUS_CHATS_DIR` 可以把整个位置换掉，界面测试时一定要设，免得往真实的「文档」里写。删除对话只删聊天记录，不动文件夹。对话页右上角的文件夹按钮（引擎自带）能打开它。

引擎要求每个会话属于某个工作区，新对话页没有工作区时连输入框都不可用，也没有给这件事留扩展点。`ui/client/chats.ts` 的做法是：读工作区列表时在前面加一个虚构的工作区「对话」，成员是所有不属于用户自己添加的工作区的会话；再包住引擎 `uiWorkspace` 服务的三个方法，让「新会话」和启动时默认落在「对话」里。引擎服务端不知道这个工作区，所以侧栏上它那一行的工作区菜单用样式收起来了。从真实工作区那一行的加号新建，仍是引擎原来的行为。引擎第一次启动会自己建一个「默认工作区」（`文档\deepseek-harness\default-workspace`），我们不用它：启动时发现它登记着就取消登记，目录、文件和会话都不删，会话改显示在「对话」里。启动时还会把用户自己添加的工作区都展开，否则它们不是当前分组，引擎会把它们折叠起来，看着像会话没了。**引擎升级后这一块要对着 `dsh-client-ui-workspace` 重新核一遍。**

新对话页的 Agent 模式切换、设置里的「Agent 预设」和「内置插件」在 `app.patch.yml` 里关掉了（`ui-agent-preset`、`ui-settings-plugins`、`ui-settings-plugin-inventory`），只收起界面，引擎里的预设和插件照常工作。

## 对话的权限

输入框下面的权限有三档：仅可查看、工作区内修改（新会话默认）、完全权限。前两档靠一道文件沙箱：助手运行的命令和写文件的工具只能改会话自己的文件夹，Windows 上命令是在一个降了权的进程里跑的。它是给在代码仓库里干活的编程助手设计的，照原样用在我们的对话里有两处对不上：

- 对话的文件夹是 `文档\CampusAgent\<日期>\<时分>`，校园命令却要把登录状态和缓存存到应用数据里的 `zju` 目录，下载的课件、转写、讲解落在 `文档\CampusAgent` 下面各自的文件夹，都在这个文件夹外面。2026-10-12 的一次真实对话（默认的「工作区内修改」，让它查 CC98）：`zju.ts` 写登录状态时报 EPERM，模型没看出是沙箱挡的，转头去读引擎那份修文件夹权限的技能，只好打断。在这之前应用里没有真的跑过校园命令，所以一直没发现：默认的档位下，第一条校园命令就是坏的。
- 降了权的进程起不了带管道的子进程，也连不上命名管道（引擎文档里写明的边界）。校园命令里的 ffmpeg、转写、读文档，还有公众号（连壳开的管道），在里面都做不了。

2026-10-12 改成对话有自己的范围，代码在 `ui/profile/permissions.mjs`：

- **对话里能写的是整个 `文档\CampusAgent`**，不只是这一次对话的文件夹：各次对话的文件夹、课程、讲解、转写都在里面，别处照旧要先问。相对路径还是从对话自己的文件夹算，放宽的只是围栏。认的是会话的文件夹在不在对话总目录下面（`CAMPUS_CHATS_DIR` 换掉总目录时跟着换）；用户自己添加的工作区不变。助手在一个对话里第一次运行自己写的命令时，引擎要给整个 `文档\CampusAgent` 登记一遍写入凭据（把里面的文件走一遍），只有这一次慢一点。
- **应用自带的校园命令不进沙箱**，三档都一样：整条命令就是 `node <core>\zju\scripts\zju.ts …` 或 `node <core>\weread\scripts\weread.ts …`（名单是 `TRUSTED_SCRIPTS`）。认的是整条命令的样子（`trustedCommand`）：`node` 后面直接跟名单里的脚本，其余每个词都是字面量；有管道、分号、重定向、变量、子表达式、换行的都不算，`node` 和脚本之间带选项的也不算（`-e`、`--require` 能带进别的代码），结尾的 `2>&1` 可以有。拿不准就不算，照旧在沙箱里跑。learn 的引擎脚本（`build.mjs`、`lint.mjs`、`shots.mjs`）不在名单里：它们会执行讲解里的脚本，那是助手自己写的代码。前两档下它们起不了 esbuild 和浏览器，助手照引擎的办法为这一条命令申请完全权限，弹出来问一次。
- **告诉模型的话跟着改**：引擎每一轮告诉模型「只能改这次对话的文件夹」，我们在它后面补两句，一句是对话里实际能写的范围，一句是校园命令单独一条执行、后面不要接管道和重定向。只在前两档出现。

引擎没有给这两件事留扩展点：策略里一个会话只有一个可写的根，而且写文件的工具拿这个根当相对路径的起点，所以不能直接改策略。做法是包住两个服务的方法，`ctx.shell.resolve`（每条 pwsh 命令执行前定策略的地方）和 `ctx.fs.checkedTarget`（写文件、改文件的工具过围栏的地方），写法和界面那边的 `chats.ts` 一样，挂在服务对象自己身上，撤掉就露出原来的。**引擎升级后对着 `dsh-pwsh-sandbox`、`dsh-fs-sandbox` 重新核一遍**；方法不在了会在日志里提示，范围退回引擎原样。

试过没有做成的一条：让沙箱里的命令也能写校园命令的数据目录，这样接了管道的校园命令也能用。把工作区的写入凭据登记到那个目录上是登记得上的（用引擎的 `AclWriteGrant` 实测过，沙箱里的进程写得进），但这台机器上的 PowerShell 是商店版，它在沙箱里连 `AppData` 都看不到：目录明明在，`Get-Content` 说路径不存在。所以**接了管道、分号、重定向的校园命令在前两档下仍然会失败**（读不到登录状态），靠上面那句话让模型不这么写；输出太长时引擎自己会存成文件。

验证：`ui/profile/permissions.test.mjs`（哪些命令算、哪些不算，包括弯引号这类 PowerShell 也当引号的写法；对话里放宽、工作区里不动；包上去、撤下来）。在隔离的数据目录里把引擎真的起来试过：两个方法都包上了；默认档位下 `zju.ts` 是不受限跑的，接了管道的仍在沙箱里；对话文件夹和 `讲解\` 写得进，对话总目录外面写不进；写文件工具的围栏同样。又在隔离实例里用真实模型发了一句「查一下学工部最近的通知」：默认的「工作区内修改」，模型收到了补的那两句，`zju.ts notice list`、`notice sources` 都跑完了，没有 EPERM。同一天又在真实的数据目录里（填着账号）走了一遍：默认档位下重发那句「帮我查找CC九八上的情感内容」，六条 CC98 命令都拿到了结果，46 秒答完，上次写不进去的 `zju\sessions\cc98-anchorite.json` 写进去了；再让它用 PowerShell 各建一个文件，对话文件夹里的建成了，`D:\` 根目录的被拦住（`[sandbox: file access denied under workspace-write mode]`），模型照补的那句话说对了能写的范围，没有去申请更高权限。**没验证的**：learn 在前两档下申请权限的那一问；别的系统（现在只在 Windows 上发布）。

## 助手的底层说明

引擎的系统提示原本是给编程助手写的。2026-10-07 的一份真实对话日志里，模型收到的开头是「You are an AI agent powered by DeepSeek Harness.」「You are a coding agent powered by the deepseek-flash model.」，后面还有两段：引擎的源码在哪（指到的是我们的项目目录，装好的应用里是安装目录）、它的网页界面怎么开发。问它是谁，答的是「DeepSeek Harness 中的编码智能体」。`app.patch.yml` 里写过的那句中文人设没有到模型那里：引擎的每个 Agent 预设（`dsh-web-app/presets/standard.patch.yml` 等）自己带一条人设，会把 `system-prompt` 那一行写的盖掉。

2026-10-11 换成我们自己的，两处：

- **`core/AGENT.md`** 是底层说明的正文，每次对话都在：助手在哪、对面是谁（学生本人，多数不是学计算机的）、应用里有哪几页、怎么回答、手里有哪些技能、东西放哪（学习页是照文件夹画的，放错了等于没做）、记忆、备忘录、技能各在什么时候写、什么事要先问（会改动学校系统、会发出去、会花钱的）、运行环境。具体一件事怎么做不写在这里，写在各个技能里。改它不用重新打开应用，下一轮对话就生效。
- **`ui/profile/agent.mjs`** 把它放进系统提示（一段，名叫 `campus-agent`，排在人设后面、引擎讲各个工具怎么用的那些段前面，里面的花括号不做替换），并在每次拼系统提示的最后一步（引擎的 `system-prompt/assemble`）做两件事：把预设带的那条「coding agent」人设换成我们的一句（`PERSONA_TEXT`，模型的名字只有这一句能带上）；去掉引擎写给改引擎的人看的三段（`harness:identity`、`harness:source`、`app:web-surface`）。引擎讲工具怎么用的那些段、工作目录那一句、交付文件怎么引用那一段都留着。

原来放在 `host.mjs` 里的 `campus-profile-policy` 一段（三样资料各记各的）并进了 `AGENT.md` 的「留下来的资料」一节，文字没改。`app.patch.yml` 里那句不起作用的人设删了。

验证：`ui/profile/host.test.mjs` 核对这一段在、三段被去掉、人设被换掉、别的段不动。在隔离实例里真开了一个对话，从它的会话日志里读出模型实际收到的系统提示：开头是我们的人设和 `AGENT.md`，「DeepSeek Harness」「coding agent」和那两段都不在了，工作目录那一句还在。要再看一次，解 `%APPDATA%\CampusAgent\home\sessions\<对话>\session.v4.jsonl.zstd`（一帧一帧接起来的 zstd）里 `system/message` 那一条。**没验证的：换了以后模型答得怎么样**，那一次对话是在没有 API Key 的隔离实例里发的，只走到发请求之前。

引擎自己还会读一份用户级的 `AGENTS.md`（`%APPDATA%\CampusAgent\home\AGENTS.md`，没有这个文件就什么都不加），以用户消息的身份放在对话最前面。没有用它装底层说明：它在数据目录里，升级带不过去，而且引擎明说它压不过系统提示。以后要给用户一个「自己写几句长期的要求」的地方，可以接它。

## 返回

我们自己的页面里，点进去的那一层（作业详情、备忘的单条和编辑、插件详情、技能详情、设置里的记忆）顶上都有一行返回，是 `ui/client/controls.tsx` 的 `Crumb`。它在场时，下面几种输入也算点了它（`ui/client/back.ts`）：

- 鼠标侧键的后退。有两条路进来：页面自己收到的鼠标事件（`button` 是 3）；壳把系统的「浏览器后退」命令转过来（`desktop/main.cjs` 听 `app-command`，经 `preload.cjs` 变成窗口上的 `campus:back` 事件）。同一下按键两条路可能都到，300 毫秒内的第二次不算。
- 键盘上的 Alt+← 和后退键。

引擎不用浏览器的历史记录，壳原来也不处理后退，所以是直接认这几种输入，没有往历史记录里写东西。几个返回同时在场时认最后出现的那个（设置面板盖在页面上时是面板里的）；上面盖着确认框（删除、放弃修改）时不动；编辑到一半按后退，和点返回一样先问要不要放弃修改。新做的页面只要顶上用 `Crumb`，不用再写别的。

验证过的是模拟出来的这几种输入（隔离实例里派发鼠标事件、`campus:back` 和键盘事件）；真实鼠标的侧键没法在离屏窗口里按，要在应用里实际按一下确认。

## 关闭窗口和托盘

设置 → 通用设置里有一个开关「关闭窗口时隐藏到系统托盘」，默认关：点关闭按钮就是退出应用。打开后点关闭按钮只把主窗口藏起来，引擎照常运行，托盘上多一个图标：点它把窗口叫回来，右键菜单里有「打开主窗口」和「退出」。窗口藏着时再打开一次应用，也是把它叫回来。Windows 11 默认把新图标收在任务栏的「显示隐藏的图标」里。

开关的值由壳自己存在 `%APPDATA%\CampusAgent\shell.json`（`desktop/tray.cjs`），页面经 `preload.cjs` 给的 `window.campusShell` 读和改（`ui/client/TrayRow.tsx`）；不在壳里打开时没有 `campusShell`，这一行不出现。托盘图标用的是程序自己的图标，只在开关打开时才有。阅读窗口和讲解窗口不跟着藏，关机、注销时也不拦。

验证过的：在隔离实例里给主窗口发关闭消息（和点关闭按钮是同一条路）、点真实的托盘图标、再启动一次、关掉开关后再关窗口。页面里的 `window.close()` 不走这条路，会直接关掉窗口。托盘右键菜单里的两项只在 `desktop/tray.test.mjs` 里用假的托盘测过，没有真的点。

## 检查更新

装好的应用会自己查新版本：启动后十五秒查一次，之后每六小时一次；设置 → 通用设置里的「检查更新」一行可以手动查，也看得到走到哪了。有新版本就自己下载（一整个安装程序，约 310 MB），下完弹窗问「立即安装并重启」还是「稍后」：选前者应用关掉、静默装好、自己重新打开；选稍后，那一行留着「安装并重启」，下次退出应用时也会装上。开发时（`npm start`）不查。

新版本取自 GitHub 上这个项目的 Release（`electron-updater`，更新源是 `package.json` 里 `build.publish` 那一项，打包时写进成品的 `resources/app-update.yml`）。仓库是私有的，用的人都是它的协作者，所以每个人用自己的 GitHub 身份去读，按这个顺序找令牌：环境变量 `GH_TOKEN` / `GITHUB_TOKEN`；设置里填的（读不到更新时那一行会出现一个输入框，用系统的加密存在 `%APPDATA%\CampusAgent\update-token`）；本机 GitHub CLI 的登录（`gh auth token`）。都没有，或者这个身份看不到仓库，那一行会写明读不到。令牌只要能读这个仓库的内容就够。

**发版时 Release 里要放两个文件**，都在 `dist` 里：`CampusAgent-Setup-<版本>.exe` 和 `latest.yml`（0.1.2 及以前还有一个 `.exe.blockmap`，安装程序改成 zip 以后没有了，见「命令」）。应用靠 `latest.yml` 知道最新版本是哪个、安装程序叫什么、校验值是多少；少了它，装着旧版本的应用会报找不到更新。Release 不能是草稿或预发布，标签是 `v<版本>`。带这项功能的第一个版本是 0.1.3，更早的版本要手动装一次。

代码：`desktop/update.cjs`（状态、定时、找令牌），在 `desktop/main.cjs` 里接上 `electron-updater`、弹窗和存令牌；页面经 `preload.cjs` 的 `campusShell` 读状态、点按钮（`ui/client/UpdateRow.tsx`）。

验证过的：装一个版本号改成 0.1.1 的测试包，让它对着真实的私有仓库查到 0.1.2、用本机 GitHub CLI 的身份下载完、弹窗、点立即安装后装好并自己重新打开成 0.1.2。没验证的：在设置里填令牌这条路（只有单元测试）、定时自动查（只测了手动点检查和定时器的设置）、选「稍后」之后退出时安装。自己重新打开的那一次不带启动参数，用的是默认的数据目录。

## 看网页的窗口

页面里点开的链接（通知原文、公众号文章、对话里的网址）都在应用自己的一个窗口里开，不去系统浏览器（`desktop/reader.cjs`，在 `main.cjs` 里接到主窗口的「开新窗口」上）。原因是用户提的：系统浏览器里要重新登录统一身份认证和 WebVPN，还可能把应用存着的会话顶掉。引擎自带的右边栏浏览器在我们这种组合下是关着的（它只在配置名叫 `desktop` 时打开），没有用它。

这个窗口复用 ZJU Core 已经登录好的会话，走法和 Core 自己访问校内网站时一样：

- 打开前把 Core 存下的统一身份认证和 WebVPN 的 cookie（`%APPDATA%\CampusAgent\zju\sessions\` 下的 `zjuam.json`、`webvpn.json`）放进窗口自己的会话里。只放这两样、只放 `zju.edu.cn` 下面的；各个网站自己的登录状态由它们经统一身份认证各自建立。窗口的会话不落盘，关了应用就没了。
- 校内网站怎么走看插件页「校园账号」里选的访问方式：默认经 WebVPN，选了校园网直连就直连。经 WebVPN 时统一身份认证仍然直连（登录状态在本机，不在 WebVPN 那边）：页面被带去 WebVPN 形式的统一身份认证地址时改成直连的；它带着票据跳回校内网站时，再把地址改写成 WebVPN 形式。地址改写的写法和 Core 一样，只是不带结尾的 `vpn-12-o2` 标记（那个标记让 WebVPN 原样返回内容，这里要的是它改写好链接的页面）。
- 标注为公网可达的网站不绕 WebVPN，直连：Core 里实测过的几个（教务网、学在浙大、智云、三全育人），加上通知模块的逐站标注表（见下）。没标注的校内网站一律经 WebVPN，它公网的、校内的都到得了。
- 存着的会话过期了（落到了统一身份认证或 WebVPN 的登录页），让 Core 自己重新登录一次（`zju zjuam session login` / `zju webvpn session login`），再放一遍 cookie 重开，不让用户在这个窗口里输密码；每个系统只试一次，登录不上就在窗口里说明原因。WebVPN 的会话存了超过五个半小时（Core 按六小时算过期）时，打开前先续上。
- 教务网这类网站不会自己把人带去统一身份认证再带回来，没登录时只会被带到它自己的登录页。打开它的页面之前，窗口先到统一身份认证为它换一次票（`reader.cjs` 的 `SITE_LOGINS`，换票地址和 Core 的教务网模块用的是同一个），换好了再开要看的页面；同一个应用运行期间每个网站只换一次，它自己的登录状态中途没了会再换一次。第一版没有这一步，用户点教务网的通知还是停在登录页（2026-10-09）。
- 窗口报给网站的浏览器标识和 Core 发请求时用的是同一个：登录状态是 Core 建立的，对学校那边应当是同一个浏览器。
- 每一步去了哪、为什么换路、登录续上没有，记在 `%APPDATA%\CampusAgent\reader.log`，只有主机和路径，不记问号后面的内容（里面有票据）；超过 200 KB 清空重记。用户说打不开时先看它。
- 只有一个窗口，再点别的链接在同一个窗口里换；页面里要开新窗口的链接也在这里开。鼠标侧键和 Alt+←/→ 后退前进，F5 刷新。只开 http 和 https 的地址。

通知模块的逐站标注表是 `core/zju/lib/notice/hosts.json`：通知用到的 69 个网站（来源表里的部门站，加 44 个学院的官网和办公网）各自是 public（公网可达）还是 campus（只在校园网里），以及打开通知栏目要不要统一身份认证。它由 `core/zju/scripts/notice/hosts.ts` 生成，要到一台不在校园网里的外部主机上实测（本机有隧道，测出来全是可达，见 `core/zju/lib/webvpn/README.md`）：

```bash
node core/zju/scripts/notice/hosts.ts --via server
```

`--via` 给 `~/.ssh/config` 里的主机别名；只读，每个网站只请求一个通知栏目的列表页；一个都没连上时不写表。2026-10-09 由用户从 `server` 跑出来的结果：69 个网站里 public 50 个、campus 19 个。campus 的是本科生院（`bksy`）、研工部（`ygb`）、团委（`zjutw`）三个部门站，13 个学院的办公网（`office.*`、`*.office.*`、`doe-oa`、`bmsoa`、`oca`），以及 `literature`、`cspo`、`che.cn` 三个学院站点，全部是从校外连不上；public 里要统一身份认证的是信息技术中心（`itc`，测出来的：通知栏目会跳去登录）和教务网（`zdbk`，取自教务网模块自己的声明：它不是网站群的站，脚本只能测首页，首页不跳登录，但读通知要登录；第一版表漏标了，用户指出后补上）。教务网、本科生院这两个的 public / campus 和更早的实测一致。标成 public 只说明那个栏目的列表页校外看得到，同一个网站上个别只给校内看的文章不在此列。没有这张表时，除了实测过的那四个站，校内网站都经 WebVPN，功能不受影响。来源表或学院名录变了以后重跑；`desktop/reader.test.mjs` 会核对每个通知网站都在表里，漏了会报出来。通知模块读通知也按这张表选路（2026-10-09 用户要求）：模块仍声明为 `network=campus`，另把表里 public 的主机列进 `publicHosts`，传输层（`core/zju/lib/webvpn/transport.ts`）对这些主机直连，其余照旧经 WebVPN；访问方式选了校园网直连时本来就全部直连，不受影响。有两种情况一个主机会在这一次命令里改回 WebVPN：直连不通（标注过时了，或者这台机器的网络到不了）；网站把校外的访问挡到了「无权访问」页（网站群对只给校内看的页面这样做，地址是 `/nopermit_zjusub.jsp`，状态码照样是 200，所以要专门认）。阅读窗口遇到这一页也同样处理：把这个网站改成经 WebVPN，重开原来要看的那一页。`zju notice sources` 的结果里每个来源带一项 `network`，不联网就能看出表有没有读到。

**这一改没有用真实网络验证过**（写的时候沙箱连不出去）：验证过的是选路的单元测试、`notice sources` 读到了表、阅读窗口的离线场景。有一个没法在本机确认的风险：网站群的列表页如果对校外访问会少列几条（把只给校内看的通知直接从列表里去掉，而不是点开时才挡），直连读列表就会漏掉它们；用户自己的机器上有校园网隧道，直连出去也是校内地址，看不出这个差别。要确认得从校外的机器直连读一个列表，和经 WebVPN 读到的逐条比。

验证：`desktop/reader.test.mjs`（地址改写和 Core 一致、怎么选路、认登录页和「无权访问」页、cookie 怎么放、标注表覆盖每个通知网站、通知模块按表选路）。窗口在真的 Electron 里的行为用假的 WebVPN、统一身份认证和校内网站离线跑过十四种情况（都有效、统一身份认证过期、WebVPN 过期或失效、直连、标注为公网的站、公网站上只给校内看的一篇、教务网要先换票的三种、校外网站、Core 登录不上），请求顺序和设计的一致。**没有连真实的学校网站验证过**：真实 WebVPN 改写页面的细节、真实的统一身份认证跳转，要在应用里点一条通知实际看。

## 执行过程（右边栏）

右边栏的「执行过程」页签把这次对话里的工具调用画成一张线路图，给不看命令的人看：助手查了哪些网站、每一步拿到了什么。一根细线从「你的问题」画到「回答」，这根主线是助手自己；每去一个网站，从主线弯出一条支线，圆圈在支线上，线的左边是网站名，右边是在那里做了什么，行尾是拿到几条。三种关系三种画法：换了一个网站，另起一条支线；接着在同一个网站上做别的，竖着接在圆圈下面（网站名不重复写）；同一步里去的几个地方，共用一条从主线弯出来的竖线，各自横着挂在这条竖线上，谁也不挂在谁下面。线都往下走，除了分出去的地方和拐进圆圈的那一下是弯的，其余都是直的。只用黑白灰，失败的才是红的（行尾写「失败」）；没有表头、标签和色块。圆点分三种：问题和回答是实心的，在主线上；查了一个网站是空心圈，在支线上；读写文件这类本地操作是小灰点，在主线上。点一行，详情（用时、拿到的前几条、失败的原因、原始命令）接在它下面。更早的几轮各折成一行。一次调用一行，不合并：同一种动作做了几次就是几行，本地操作也一步一行、不收起（2026-10-11 用户要的：步骤多才看得出它做了多少事）。顶上一句写去了哪几个网站、一共多少步；每一行名字后面写这一次针对什么（哪位老师、搜的什么词；命令里只有编号时，用结果里那一条的标题），纯数字的编号不写。

现在的样子见 `计划/执行过程页-一步一行.png`（一轮选课，15 步：教务网读课表、搜课、查教学班，查老师和 CC98 同时发出，再同时查三位老师、开三个帖子。这张是把 `TraceTab.tsx` 用编好的数据画在隔离实例的页面里截的，样式是真的，数据是假的）。`计划/执行过程页-支线画法.png` 是合并还没去掉时的同一种画法（同一种动作的几次合成一行，写「3 次」）。`计划/执行过程页-选课.png` 是同一轮在应用里的截图，画法是上一版的：所有站都串在主线上，只有同一步里的才分出去并排。2026-10-09 改掉它，是因为一根线把站穿起来读着像「后一个接着前一个」，换了网站也看不出来；而引擎没记谁依赖谁，所以现在只画「同一个网站接着做」「换了网站」「同时发出」这三样，不画依赖。

2026-10-08 试过照 Git Graph 做的一版（彩色的线、带表头的表格、左边带一条色块的网站标签），用户看了觉得俗气，换成了现在这样；以后不要往回改。

**用的时候自己打开，向右打开**（2026-10-12）。发出问题、助手开始做事时，右边栏自己展开到「执行过程」（`trace/install.ts` 的 `installAutoOpen`，听的是引擎给的「这一轮开始了」）。一个对话只自己打开一次：之后人把它收起来，这个对话里不再自己打开，换一个对话照样会开；窗口窄于 768 时引擎会把右边栏铺满窗口盖住对话，这时不开。右边栏打开时窗口向右加宽，中间的对话不被挤窄；收起时窗口缩回去。引擎原来的做法是右边栏从对话区里让出一列，第一次打开占窗口的 45%：1280 的窗口里对话区从 1000 被挤到 424。现在分两头：

- 页面（`ui/client/rightpane.ts`）：右边栏第一次打开的宽度改成 420（人拖成多宽之后就是多宽，应用开着的这段时间里记着）；从引擎框架那一行（三列的网格）上读出右边栏现在占多宽，报给壳。引擎没有把这个宽度交出来，是读它写在元素上的列宽和 `data-rightbar-collapsed`、`data-rightbar-fullscreen` 两个标记；存宽度的动作也不在它公开的接口上（`ctx.layout.panels.setRightbar`）。**引擎升级后对着 `dsh-client-ui-layout` 的 AppFrame 重新核一遍。**
- 壳（`desktop/pane.cjs`）：窗口加宽多少、往哪加。先往右加；右边到了屏幕边上，不够的部分把窗口往左挪着加（收起时挪回来，人自己动过窗口就只缩宽度、不往回挪）；还不够就只加这么多，差的部分照引擎原样从对话区里让。窗口最大化、全屏时不动，这时和原来一样是挤对话区，只是右边栏窄了。加了多少记在壳这边，页面重新加载后再报一次不会重复加。窗口是在 160 毫秒里拉开的，系统设了减少动效时一步到位。没人动过窗口时，按壳自己上一次摆的数来算，不按读回来的数：屏幕缩放不是整数倍（125%、150%）时，窗口的位置设进去再读回来会差一个像素，拿读回来的数一加一减，开合一次窗口就宽一个像素；认「人动过没有」也留了两个像素的余量，不然差这一个像素就被当成动过，收起时往左挪的那一段不还（这两处都是 2026-10-12 在 150% 的屏幕上实测出来的）。

窗口加宽要经过壳，比页面慢一两帧，等它的话这一两帧里对话会先被挤一下再弹回来。所以右边栏一出现，页面先把引擎的框架钉成「窗口现在的宽度 + 右边栏」那么宽（多出来的一截在窗口外面，看不见），对话区一个像素都不动，窗口再拉开把右边栏露出来，到位以后放开。收起时框架连同它的三列都钉成收起之前的样子，右边栏原样留在它那一列，由窗口的右边一点点盖过去，到位以后放开。引擎打开、收起右边栏时自己有一段「从右边滑进来、往右滑出去」，钉着的时候不要它（`style.css`「右边栏向右打开」一段，认的是引擎右边栏里的 `data-dockkit-*`，**引擎升级后对着 `dsh-client-ui-sidebar-right` 的样式重新核一遍**）：照它来，打开时露出来的那一截先是空的，收起时右边栏会被挤到对话上面再滑走。放开用的是定时器不是「下一帧」，窗口被别的窗口盖住时页面不出帧。拖右边栏的边改宽度时不跟，松手以后窗口按最后的宽度调一次。切到没有右边栏的页面（插件、校园事务、学习）时窗口也会缩回去，回到对话再加宽。不在壳里打开（浏览器）时没有这一段，只有 420 这个默认宽度。

**图是长出来的**（2026-10-12 用户说的：现在是直接冒出来的，要像树一样生长）。一行接一行往下长，隔 80 毫秒一行（`TraceTab.tsx` 的 `useGrowth`）：一行出现时，它自己从没有高度长到一行高，把下面的行慢慢推下去；线沿着走向画过去（长度归成 1，虚线的偏移从 1 走到 0）；线画到了，圆点才弹出来；字最后淡进来。线是按同一个速度画的，主线一行正好画一步那么久，所以上一行画到底、下一行正好接上，看着是一根线一直往下长；每一段线等多久、画多久写在 `style.css`「长出来」一段的注释里。几件要记着的事：放出下一行认的是行的身份不是个数（中间插进来一行时，下面已经在的行不会被收回去重长一遍）；一下子多出来很多行（刚打开页签、点开更早的一轮）时一次长几行，整张图在一秒上下长完；一行早就在了、后来才多出来的线（下面又接了一站）不排队，马上画，排不排队在线挂上去的那一刻定下来之后不变（画到一半改延时会跳一下）；系统设了减少动效时全部直接出现。

代码在 `ui/client/trace/`，页签本身是 `ui/client/TraceTab.tsx`：

- `model.ts`：数据从哪来。向引擎的 `uiConversation` 登记两个 Definition（工具调用、用户的提问）和一个 View，引擎按会话把事件喂过来，对话进行时实时更新；页签用 `uiConversation.binding(sessionId).target('campus-trace')` 订阅。写法照引擎自己的 `ui-tool/todo-history`。
- `parse.ts`：把一次调用翻成人话。会话里的校园命令是 `pwsh` 加一整条命令，从里面认出 `zju.ts` 后面的「模块 对象 动作」；网站的名字在 `sites.ts`。
- `steps.ts`：每一步叫什么。把一条命令说成助手正在做的一件事，动词开头、十个字上下（「查教学班的老师、时间和余量」「查老师的评分和学生评价」）：太短看不出在干什么，照搬命令说明又一行放不下（2026-10-11 用户定的：这页的用处就是把看不懂的命令变成看得懂的过程）。成对的命令加 `--cancel` 时另起名字。`commands.gen.ts`（由 `gen-commands.mjs` 从命令树生成）只用来认命令，和没起名字时拿说明的第一句顶着。core 加、改、删了命令：运行 `node ui/client/trace/gen-commands.mjs` 重新生成，再在 `steps.ts` 里补上或删掉名字，`npm run test:trace` 两样都查。
- `route.ts`：怎么拼成路线。引擎只记了「轮 → 步 → 同一步里并行的调用」，没有谁依赖谁，所以只按这个画：一次调用一站；同一步里发出的几次调用是同一个岔口的几条支线；下一步的调用能各自接上（先找最后一站是同一种动作的支线，再找同一个网站的，接在它下面，一条支线只接一次）就接，有一次接不上就另起岔口；读写文件、跑脚本这些本地操作一次一站排在主线上，夹在中间时把前后的支线隔开。岔口里靠上的支线接着做时，新的一行会插在中间，所以岔口里的几行不严格按时间排。

行尾能显示多少取决于命令的输出：输出完整时数出条数、取前几条标题；输出太长被引擎截掉开头，或者模型把输出导进了文件，行尾就空着。末尾的 `[exit code: N]` 不拿来判断成败（PowerShell 里命令只要往 stderr 写过东西，成功了也是 1）。实际访问了哪些主机现在不知道，网站名是按模块对的。

验证：`npm run test:trace`（含「`commands.gen.ts` 和 core 的命令树一致」这一条，和 `ui/client/rightpane.test.mjs`：读列宽、什么时候钉住框架）；`desktop/pane.test.mjs`（往右加、往左挪、放不下、最大化、人动过窗口、缩放不是整数倍、一步步拉开）。在隔离实例里用真实对话看过（100% 的屏幕、右边有地方）：发出问题后右边栏自己打开，窗口在 160 毫秒里从 1280 加宽到 1700，其间每次量对话区都是 1000；收起时缩回 1280；切到插件页缩回去，回到对话再加宽。又在真实的数据目录里、150% 缩放的屏幕上走了一遍（窗口右边只剩 332，走的是往左挪的那条路）：打开时往右加到屏幕边、往左挪 81，对话区宽度不变（取整差 1 像素）；开合四次，位置和宽度每次都回到原处；拖右边栏的边拖宽 100、再拖回去，松手后窗口各跟着调了一次，对话区回到原来的宽度；同一个对话里收起以后再发一句，没有再自己打开；用系统的窗口抓取（`PrintWindow`，抓的是真正要显示的内容）把打开、收起各录了一遍，对话没有跳，右边栏是被窗口露出来、盖过去的，线路图在露出来的同时往下长。**录的时候要注意**：调试协议的截图在窗口移动、变宽的那一两百毫秒里取到的是不同步的画面（左栏不见、内容错位），不能拿它判断过渡；窗口被别的窗口盖住时页面量出来的尺寸是旧的，要带 `--disable-features=CalculateNativeWinOcclusion` 启动才量得准。**没验证的**：窗口最大化时的退路（只有单元测试）；多块屏幕之间；真实使用里一轮十几步时动效的观感。

- `engine/build.mjs` 定成品放哪的那一行：那边按「引擎所在文件夹的上一级」找 `dist\`，应用里引擎在安装目录、讲解在用户的工作区，改成按这一讲自己的位置（`<根>\lessons\<主题>\film`）找。在那边的布局下结果一样。

`tools/tts/README.md` 里还写着 `D:\Learn\` 的路径，是照搬的；应用里没有 IndexTTS，配音这条线用不了，成片只有画面和字幕。

两份技能原来各有一份自己的 Profile，接进应用后各归一处，互不混用：

| | 原来的 Profile | 现在在应用里 | 存在哪 | 谁读谁写 |
|---|---|---|---|---|
| ZJU Core | `profile.env` 里的账号、密码、访问方式 | 「插件」页，各个校园功能的详情页 | `accounts.json` | 人在页面上填，ZJU Core 只读；不给模型 |
| ZJU Core | `profile.env` 里的学籍（学院、专业、年级、培养层次） | 设置里「个人档案」最上面的基础信息 | `identity.json` | 人在页面上填或从教务网读取，ZJU Core 只读；模型看得到，不能改 |
| Learning Core | `profile.md`（学的人已有的基础，一门课一节） | 设置里「个人档案」下面的记忆，一门课一条，带「课程」标签 | `memory/*.md` | 人在页面上改，助手用 `campus_profile_read` / `campus_profile_write` 读写 |

ZJU Core 这一侧的接入只有一张表，`ui/profile/catalog.mjs`：插件页上有哪些校园功能、每一项管 ZJU Core 的哪些模块、要填哪些账号、基础信息有哪几项。引擎侧（开关、账号文件、基础信息）和页面（插件页、账号表单、设置里的个人档案）都从这张表取，改一处即可。ZJU Core 按同样的键名读（`core/zju/lib/profile/profile.ts`）。`ui/profile/catalog.test.mjs` 核对两边对得上：每个插件管的模块在 core 里真有、每个模块只归一个插件、账号和基础信息的键一致、core 的报错里叫用户去填的插件名是页面上真有的。

Learning Core 这一侧没有表，是一条约定，写在 `core/learn/SKILL.md` 的「观众的基础」一节：读哪些记忆、怎么认定、缺了怎么补、记忆怎么写。原 `profile.md` 里的「认定方式」是给执行者的规则，只放在这一节；「已修课程」「正在学」是个人资料，在记忆里，记忆里不写规则。

ZJU Core 和原技能其余不一样的地方：

- 没有 `profile.env`，`profile init` 也去掉了；账号和密码只从 `accounts.json` 读，不认同名的环境变量。
- 运行数据（会话、缓存、下载）默认放在档案目录旁边的 `zju/`，也就是 `%APPDATA%\CampusAgent\zju`，不落在代码目录里（`core/zju/lib/core/paths.ts`）。
- 档案目录由桌面端经 `CAMPUS_PROFILE_DIR` 给出，引擎启动的命令会继承它。
- 定时和文件交付的说明按应用改了（2026-10-11）；原技能在服务器上由 Hermes 调用、结果发到 QQ。`references/schedule.md` 原来写 Hermes 的定时任务、服务器的工作目录、已有的签到任务和同机的服务，现在写引擎的自动化任务：助手用 `schedule_create`、`schedule_list`、`schedule_update`、`schedule_delete` 建和管，任务绑在建它的那个对话上，到点把提示词作为一条消息发回那个对话，应用开着才会发；「自动化任务」关着时没有这四个工具，说明里让助手请用户去插件页打开。`references/tyys.md` 指向它的那一句跟着改了。`SKILL.md`「文件交付」去掉了给 QQ 发附件的 `MEDIA:` 写法：文件就在本机，用下载结果里的原路径，回答里怎么给照 `core/AGENT.md`（给链接）。工具名和到点的行为是对着 `@deepseek-ai/dsh-schedule` 0.2.0-rc.2 的工具定义和说明核的，没有在应用里让助手实际建过一次任务；引擎升级后对着这个包重新核一遍。

## 智云的转写和文件落点

2026-10-09 改的，代码在 `core/zju/lib/zhiyun/`：`asr.ts`（转写）、`places.ts`（落点）、`courseware.ts`（课件提取，从原 `asr.ts` 里挪出来，没改）。

**转写不再用 Python。** `zhiyun trans audio` 原来要 uv、Python 3.12、CUDA 版 PyTorch 和 funasr，现在用引擎「语音输入」插件带的那一套：SenseVoiceSmall 的 ONNX int8 权重，经 `sherpa-onnx-node` 在 CPU 上跑。运行库已经随应用打包；模型（约 240 MB）在 `%APPDATA%\CampusAgent\home\speech-to-text\sensevoice\models`，和语音输入共用，谁先用谁下载。第一次转写时 core 自己下：清单（地址、大小、SHA-256）读插件包里的 `runtime/assets.json`，`huggingface.co` 和 `hf-mirror.com` 哪个先回应用哪个，校验通过才换成正式文件名。`zhiyun setup --component asr` 只做这一件事，`check` 只看不下。原来的 `worker.py`、`setup_models.py`、FireRed 引擎和 `--engine`、`--device`、`--batch-seconds`、`--cpu`、`ZJU_ASR_*` 都删了。

插件自己的接口（`ctx.speechToText`）转不了整节课：一段录音限 4 MB，只返回一整段文字、没有时间。所以只借它的运行库和模型，识别流程是我们自己的。

断句的设置不能照搬插件的。拿一节 148 分钟的录播（ADS《优先队列》）在本机（Ryzen 9 9950X3D、RTX 5080）比过，没有人工校对稿，用智云官方字幕当第三方参照：

| 版本 | 耗时 | 和官方字幕的差异 | 官方有、它漏掉的字 |
|---|---|---|---|
| 原来的 PyTorch 版，GPU | 51 秒 | 10.28% | 544 |
| 原来的 PyTorch 版，CPU | 163 秒 | 10.27% | 552 |
| ONNX int8，插件原样的断句 | 106 秒 | 12.29% | 1358 |
| ONNX int8，现在的做法 | 113 秒 | 10.52% | 546 |

插件的断句是给几秒钟的语音输入用的，切得碎（1719 段），每段单独识别会丢句首句尾的字。现在的做法是把相邻的段并成不超过 15 秒的一块、两头各留 0.3 秒、断句阈值从 0.5 放到 0.3，这组数写在 `asr.ts` 的 `RECIPE` 上。同样设置下 fp32 权重（938 MB）和 int8 没有差别。和 PyTorch 版剩下的差距是同音字；专业词三家都错（「摊还」都写成「瘫痪」），对照课件校正这一步省不掉。应用里的命令跑出来的结果和这次实测的那一份逐字相同。

**文件放进「文档」。** 智云下载和转写的结果原来在 `%APPDATA%\CampusAgent\zju\output`，用户找不到，现在：

```text
文档\CampusAgent\
  课程\<课程名>\第N次 日期\     zhiyun download：materials\、slides\、subtitles.json/txt、video.mp4、download.json
    转写\<文件名>\              这次课里的文件转出来的文字
  转写\<文件名>\                别处的录音、课件转出来的文字
```

一次课一个文件夹，各带自己的清单，分几次下不同的课次互不相干。`CAMPUS_CHATS_DIR` 把 `文档\CampusAgent` 整个换掉（和对话文件夹同一个开关，测试时一定要设）。指定 `--out-dir` 时还是原来的布局，Learning 往主题的 `data\` 里下载不受影响。转写时转出来的那份 16 kHz 音频（一节课近 300 MB）用完就删。顺带修了一处：所选课次里有一次课还没有字幕时，整条下载命令会报错，现在那次课记进 `skipped`。别的模块（学在、超星、知网、CC98）的下载位置没动。

没做和没验证的：

- FFmpeg 已随应用带上（见下一小节），但没有重新打包，也没有在打开的应用里让助手实际转一次。
- `zhiyun trans ppt` 仍然要 Python 环境（`setup --component ppt`，需要 uv）。
- 只测了这一节课、这一台机器；普通笔记本上的速度没测，打包后的应用里没跑过。
- 学习页当时还是占位，后来做了，见「学习」一节。

引擎升级后核对三样：包名 `@deepseek-ai/dsh-experimental-speech-to-text-sensevoice`、它的 `runtime/assets.json` 的结构、模型目录的布局（`models/sensevoice-onnx/`、`models/silero/`）。

### 自带的 FFmpeg

录音转格式、合并回放要用 FFmpeg。原来靠 `zhiyun setup --component media` 用 npm 临时装，打包后的应用里没有 npm，装不上。2026-10-09 起它是应用的依赖：根目录 `package.json` 里的 `ffmpeg-static`（锁在 5.3.0，和 core 的 `setup` 原来装的是同一个版本），装包时下好当前系统的那一份（Windows 上是 `node_modules\ffmpeg-static\ffmpeg.exe`，约 83 MB），打包时跟着 `node_modules` 进安装目录。

ZJU Core 没有为这件事改代码，它本来就认环境变量 `FFMPEG_PATH`。壳启动引擎时把自带的那一份的路径放进去（`desktop/ffmpeg.cjs`，在 `desktop/main.cjs` 起引擎的那一行接上），引擎启动的命令和应用自己跑的 core 命令都会继承。用户自己设了 `FFMPEG_PATH` 的以用户的为准。`desktop/ffmpeg.test.mjs` 核对这一份在、跑得起来，并入了 `npm run test:plugins`。

这份 FFmpeg 是 gyan.dev 的 6.1.1 essentials 构建，GPL v3；`ffmpeg-static` 这个包是 GPL-3.0-or-later。应用只把它当一个单独的程序调用，许可证文本（`ffmpeg.exe.LICENSE`）和说明跟着二进制一起分发。交材料时在第三方组件里列上它。

### 给命令行用的 Node

2026-10-11 加的，0.1.3 起有。技能里的命令都是 `node …`（`core/zju/SKILL.md` 的 `node <SKILL>/scripts/zju.ts`、`core/learn/references/animation.md` 的 `node engine/build.mjs`），由引擎的命令行工具在用户的机器上执行，找的是 PATH 上名叫 `node` 的程序。应用自己带着一份 Node（Electron 里的那一份，现在是 24.18；应用自己跑 core 用的就是它），却没有一个叫 `node` 的程序给命令行用，引擎的命令行工具也只是原样继承进程的环境。结果是：没装 Node.js 的电脑上，助手一跑技能的命令就是找不到 `node`，校园功能和讲解都用不了；装了旧版本的又跑不了 `.ts`。开发机上装着 Node，所以 0.1.2 及以前一直没暴露。

做法在 `desktop/node.cjs`：壳启动引擎时在数据目录的 `bin` 文件夹（`%APPDATA%\CampusAgent\bin`）里放一个 `node.cmd`，它把应用自己的可执行文件当 Node 用（`ELECTRON_RUN_AS_NODE`），参数原样传过去；再把这个文件夹放到交给引擎的 PATH **最前面**（在 `desktop/main.cjs` 起引擎的那一行接上），引擎启动的命令都会继承。几个定下来的地方：

- 放在最前面，系统里已经有 Node 的也用我们这一份：要的是所有机器上跑技能的是同一份 Node，用户自己装的可能太旧。开发时（`npm start`）也一样，免得只在装好的应用里才出问题。
- 应用的可执行文件在哪，不写进 `node.cmd`，经环境变量 `CAMPUS_NODE_EXE` 告诉它：`.cmd` 是按系统的代码页读的，用户名带中文时写在文件里的路径会读错，环境变量不会。文件本身全是 ASCII。
- 只放 `.cmd`，不放 `.ps1`：PowerShell 会先找 `.ps1`，而系统默认不许运行脚本，那样 `node` 反而整个用不了。
- 只做了 Windows 的。没有给 `npm`：技能日常用不到，讲解要加别的画面库时才用（`animation.md` 里的 `npm install --prefix engine/vendor`），那时仍然要用户自己有 npm。

验证：`desktop/node.test.mjs` 三项，并入了 `npm run test:plugins`。其中一项是真的起一个 PATH 里没有 Node.js 的 PowerShell，数据目录带中文和空格，在里面敲 `node`：跑起来的是 Electron 里的那一份，`.ts` 能直接跑，带空格和中文的参数原样到，退出码传得回来，脚本里用 `process.execPath` 再起的子进程也是 Node；另一项核对引擎起命令时会把这个 PATH 和 `CAMPUS_NODE_EXE` 原样带下去。装好的测试包里也看过（见「命令」里 0.1.3 的验证）。**没验证的：在一台真的没装 Node.js 的电脑上让助手跑一条校园命令**（开发机上装着 Node，只能把它从 PATH 里拿掉来模拟）。

## 留下来的东西怎么分

应用里会留下来的资料按「说的是谁」分四样，各放各的地方：

| | 说的是 | 谁写 | 助手怎么用 | 在哪看 | 存在哪 |
|---|---|---|---|---|---|
| 基础信息 | 用户（学校登记的） | 用户填，或从教务网读 | 每次对话都带 | 设置 → 个人档案 | `identity.json` |
| 记忆 | 用户（助手观察到的：学过什么、偏好、目标） | 助手自己记，用户能改能删 | 每次对话带目录，全文按需读 | 设置 → 个人档案 | `memory/*.md` |
| 备忘录 | 一件事（比赛、要办的手续） | 用户写，或用户让助手记 | 用户问到才查 | 校园事务页左栏 | `notes/*.md` |
| 技能 | 助手怎么做一件事 | 助手走通以后自己存 | 遇到同类问题时加载 | 插件页第三组 | `skills/*.md` |

记忆和备忘录的分界：主语是用户这个人的进记忆，主语是一件事的进备忘录。记忆助手不用问就写，备忘录助手不主动写。外面发来的通知是另一类，谁也不写，看过就过去，放在校园事务页右栏。

2026-10-09 之前前两样和备忘混在一起，叫「档案笔记」，放在侧栏的「个人档案」页。用户定的改法：基础信息和记忆进设置（填一次以后很少再看），备忘录和通知并进校园事务，技能进插件页，侧栏的「个人档案」一项拿掉。

侧栏固定四项：插件、自动化任务、校园事务、学习。**不再往侧栏加入口**（用户的原话：侧边入口多了会无限延长），新的内容放进已有的页面里，用分栏、分块或页内切换。自动化任务是引擎的定时任务插件自己登记的，排序号是 10；我们自己的两项在 `ui/client/panels.tsx` 里用 30、40，不能和它相同，否则谁先加载谁在前。

## 个人档案（设置里的一页）

设置面板里排在「通用设置」后面的一页（`settings.section`，在 `ui/client/index.tsx` 登记，页面是 `ui/client/ProfileSettings.tsx`）：上面是基础信息，下面是记忆。记忆可以新建、编辑、导入、导出、搜索、按标签筛、归档和删除。基础信息和记忆都不留修改历史，保存就是覆盖。导航里它的图标是齿轮：引擎按页的编号配图标，自己起的编号只有这一个可用。样子见 `计划/设置-个人档案.png`（隔离实例加假数据截的）。

先是列表（上面是基础信息，下面一行一条记忆），点开一条看全文，再进编辑，都在这一页里切换。基础信息点「编辑」后原地变成输入框。列表、单条、编辑三个界面在 `ui/client/Notes.tsx`，点开和编辑两层的切换在 `ui/client/notebook.tsx`；这两个文件校园事务页的备忘录也用，页面上的叫法由 `MEMORY_WORDS` / `MEMO_WORDS` 给。

记忆和备忘的文件格式一样，照 Obsidian 的做法，`memory/` 和 `notes/` 这两个文件夹的格式都和 Obsidian 的库一样（没有实际拿 Obsidian 打开验证过；应用只列文件夹本身和它下面的 `归档/` 这两层，别的子文件夹里的不会列出来）：

- 一条是一个 Markdown 文件，文件名就是标题，所以同一处标题不能重名，也不能有 `\ / : * ? " < > | [ ] # ^`。改标题就是改文件名，同一处别的几条里指向它的 `[[双链]]` 跟着改。
- 文件开头两行 `---` 之间是属性区：`tags` 是标签，别的每行一项「名称: 值」（学期、来源这类）。文件里没有谁写的、什么时候写的这类记录，改动时间用文件自己的。
- 正文是普通 Markdown。`[[标题]]`、`[[标题|显示的字]]` 链到同一处的另一条；页面上把它交给引擎当文件链接画（`Notes.tsx` 的 `withLinks`），点了打开那一条，还没有就按这个标题新建。
- 归档是把文件挪进那个文件夹下面的 `归档/`，取消归档再挪回来。
- 在别的编辑器里改过的照样读。属性区写坏了的也列出来并标明，打开编辑时给的是整篇原文，改好再存。

记忆这一块在页面上的规矩：

- 列表：新建和导入在「记忆」标题那一行；下面是搜索，有归档的时左边多一个「记忆 / 已归档」的切换；再下面是写明「标签」的一排标签筛选。一行只有标题和最近改动的日期，标签不跟在标题后面。
- 单条：标题一行，右边是导出、归档、删除、编辑；标题下面是属性（标签一行，别的属性一项一行，左边名称右边内容），一根细线，然后是正文。
- 编辑：标题、属性、正文三块。属性里标签用选择框（已有的标签可以直接选，也能输入新的），别的属性一行一项，可以添加和移除；正文是 Markdown，可以切到预览。
- 标签只表示这条记忆是哪一类（课程、目标、偏好这样的词），一条通常一个。它有两个用处：列表上「标签」那一排用来挑着看，最前面是「全部」；助手按它找出某一类的全部记忆（做讲解前找「课程」）。已修还是在修、学期、来源这类具体信息不放标签，放属性。
- 「移除」这类去掉东西的文字按钮，鼠标放上去变红（`data-danger`）。
- 不分「手动记的 / 助手记的」，也没有「待核实 / 已核实」。以前按最后一次是谁保存的来分，改一个字就换类，站不住。
- 归档、取消归档、删除之后直接回列表。删除是永久的，只有人能在页面上删，助手只能归档。

提示的用法和引擎一致：操作成功用 primitives 的 `Toast` 在窗口顶上闪一下；删除和放弃修改用 `Modal` 确认；出错用页面里的红色提示条，留到下一次操作。不用黄色的提示条报「已保存」这类消息。学院、专业这些在这里填；账号和密码不在这里，在插件页填。

基础信息里能选的不让手填：校区和入学年份是下拉菜单，学院按学部分两级选（名录就是 ZJU Core 查学院通知用的 `core/zju/lib/notice/colleges.json`，由 `ui/profile/colleges.mjs` 读出来；名录里没有的可以选「手动填写」），标签从已有标签里勾选或输入新的。下拉用的是引擎的菜单（`ui/client/controls.tsx` 的 `Select` 和 `TagPicker`）。

基础信息里有几项会自动填，逻辑在 `ui/profile/identity-fill.mjs`：入学年份和培养层次（本科、硕士、博士）从学号算（首位 3 本科、2 硕士、1 博士，第 2、3 位是年份）；本科生的称呼（姓名）、学院、专业从教务网读，走的是 ZJU Core 的 `zdbk student`，由引擎进程用自己的运行环境直接跑这条命令，不经过模型。研究生的学院和专业教务网里没有，专业代码和校区也没有来源，这几项手填。触发有两处：在插件页保存统一身份认证的学号或密码后自动跑一次，只补空着的项，读不到也不影响保存账号；基础信息右上角的「从教务网读取」是手动再跑一次，学院、专业、入学年份、培养层次以读到的为准，称呼只在空着时填。

## 校园事务

左侧「校园事务」放手上的事，分两栏，一样宽（`style.css` 的 `.campus-affairs-columns`；先做的是四六开，用户看了说右栏留空多，改成五五开）：左栏是要办的，上面是各系统里快到期的作业，下面是备忘录；右栏是通知。主区域不到 760px 宽时两栏上下叠放。样子见 `计划/校园事务页-两栏.png`（隔离实例加假数据截的）。

作业现在接了学在浙大和 PTA，默认只看两周内要交的，这一块右上角可以切到「全部」。一条作业一张卡片：名字、哪门课、在哪个系统，截止时间和还剩多久，不到一天的用红字，最右是「交给助手」。列表里的「交给助手」只画一个图标（`handoff.tsx` 的 `HandIconButton`，28px 见方），鼠标放上去或键盘聚焦时用引擎的 `Tooltip` 显示这四个字；带字的按钮会把窄栏里的卡片撑高，用户 2026-10-09 要求缩成图标。详情页右上角的那个仍然带字。两栏时卡片窄，用户要它尽量扁：还是横着排两行高（名字和课程在左，截止时间和还剩多久在右，最右是图标），间距收紧，课程名太长就截掉、后面的标签不换行，一张约 64px 高；作业名特别长时才会多一行。卡片上只有系统这一个标签，卡片和详情页都不另标「在线测验」这类类型（用户说不需要）。点卡片进这份作业的详情。先露出五张，再多的收起来，点「展开其余 N 项」才出来。两周内没有要交的，也会明说没有。

数据怎么来：

- 引擎侧 `ui/profile/affairs.mjs` 用 `ui/profile/core.mjs` 跑 ZJU Core 的命令（`zju xuezai todos`、`zju pta homework list`），把结果变成一条条存进缓存 `%APPDATA%CampusAgentcacheaffairs.json`，每个系统一份。再接别的系统，在 `affairs.mjs` 的 `SOURCES` 里加一行，写明用哪条命令、要哪个账号、归插件页的哪一项管。
- 页面（`ui/client/AffairsPage.tsx`）打开时先拿缓存画出来，再让后台去每个系统重新读，哪个读完就先换上哪个的结果，所以进这一页不会先看到「加载中」；只有从来没读到过的第一次会说一句在读。离开再回来、回到窗口时也是这样。页面右上角的刷新是立刻重读。
- 读成功后一分钟内再进页面不重读；读失败后五分钟内不自动重试（密码填错时反复登录可能锁账号），点刷新不受限制。这次没读到时上一次的结果留着，列表下面说明是哪个系统、什么原因。
- 账号没填的系统不去读，列表下面给一个去插件页填写的入口；插件页关掉「课程与作业」后两个系统都不读，缓存也不显示。换了账号，原来那个账号读到的缓存不再显示（缓存里只记账号的指纹）。
- PTA 里算作没做完的：还有题没答的，和已经判出有题没通过的；全部答完而结果还没公布的不算，自己交了卷的也不算。

后台读完如果多了作业，新卡片先让出位置再从左边滑进来；少了的向右滑出去，下面的补上来。一进一出都是往右走，同时有来有走时两张卡片不会在同一边交错。这套进出的动画在 `ui/client/Flow.tsx`（哪一项在进、在出、被折起）和 `style.css` 的 `.campus-flow-*`（动画本身）里，别的列表要用可以直接套。系统设置了「减少动态效果」时不滑动，直接换。

点开一份作业（详情页，和笔记详情一个排法）：上面是课程、系统、截止时间，以及状态、提交方式、能不能重交、最近一次提交；下面是老师写的要求原文和附件，每个附件旁边有「下载」；PTA 的是题目集说明和每道小题的题型、分值、对错。它也是先给缓存再去读：

- 学在浙大读列表时顺带带回了每份作业的要求，第一次点开先显示这一段，再用 `zju xuezai homework view` 读完整的（附件、提交规则、交过的记录）。PTA 用 `zju pta homework view`，按题目集的编号读。读过的详情和列表存在同一个缓存文件里，再点开直接显示；作业从列表里消失时它的详情一起删掉。
- 附件点「下载」存到 `<下载>\CampusAgent\课程名\作业名\`（`ui/profile/downloads.mjs`；不直接放进「下载」，免得把那里同名的文件换掉），用的是 ZJU Core 的 `zju xuezai homework attachments --file 附件名 --out-dir 文件夹`。下完这一行变成「打开文件夹」：在资源管理器里选中这个文件，只打开文件夹，不运行文件。下过的附件存在哪记在缓存里，重开应用后还认得；文件被挪走或删掉，这一行就变回「下载」。没下成的原因写在文件名下面。下载走 core 的分块下载器（2026-10-11 起），中途断了（应用退出、超过 10 分钟）会在这个文件夹里留下 `附件名.parts` 和 `附件名.lock`，再点一次接着下，下完自己清掉。测试时用 `CAMPUS_DOWNLOADS_DIR` 把位置换到临时目录。
- 在线测验这类读不到更多内容的，详情页只有上面几行，并说明要到原系统里打开。
- 新接一个系统时，在 `SOURCES` 那一行的 `detail` 里写「读一条用哪条命令」和「结果怎么变成详情」，有附件可下的再写「下一个附件用哪条命令」；详情的格式是固定的：正文、几行「名称：内容」、附件名、可选的一张表。

「交给助手」（`ui/client/handoff.tsx`）开一个新的对话，把一段写好的话放进输入框：哪个系统、哪门课、哪份作业、几号截止，请助手先把要求、附件和现在的进度读一遍。话不会自动发出去，用户可以改、可以补一句再发。做法是在引擎的 `conversation.input.overlay` 插槽登记一个不显示东西的组件，它拿得到这个对话的「写入草稿」操作；用这个插槽是因为它在还没发过消息的新对话里也会画出来。别的页面要把事情交给助手，直接调 `handToAssistant(一段话)`。

### 通知（右栏）

学校各部门和本人学院新发的通知，加上已添加公众号的新文章，按时间从新到旧合成一条列表（`ui/client/Feed.tsx`，引擎侧 `ui/profile/feed.mjs`）。默认只看一周内发的，可以切到「全部」。列表放在一个定高的框里自己滚动（`style.css` 的 `.campus-notice-scroll`，高度跟着窗口走，底边大致落在窗口底部），条数再多页面也不会变长；先做的是「展开其余 N 条」，用户说一展开整个页面就很长，改成了框。一行是标题、谁发的、哪天，右边是「交给助手」的图标；点一行打开原文。上次来过之后新出现的，标题前带一个小圆点（上次是什么时候记在本机的 `campus.feedSeenAt`，离开这一页时更新；第一次来都不算新的）。

- 学校通知用 ZJU Core 的 `zju notice new` 读，它只给上次之后新出现的，所以读到的攒在缓存 `%APPDATA%\CampusAgent\cache\feed.json` 里，留 45 天、最多 300 条。应用读的时候带 `ZJU_NOTICE_READER=app`，core 给它另记一份已读（`seen.app.json`），助手在对话里问「有没有新通知」用的还是原来那一份，两边互不影响。
- 公众号文章不在这里读：公众号插件自己半小时检查一遍（`ui/profile/wechat.mjs`），这里只取它已经存下的；页面右上角的刷新会催它马上再看一遍，平时进页面不催。有的号要用户处理一下才能接着读时（微信读书要验证、登录过期），列表下面多一句说明和去插件页的入口。
- 公众号的文章在列表里要一眼分得出来（用户 2026-10-12 要的）：谁发的那一格前面有一枚浅蓝底的小标签写明「公众号」，号名比学校通知的那一格深一档；学校的通知还是一行灰字。先做的是整块绿色的标签，用户说太绿、不好看；换成灰色小标签以后又说还是要一点颜色，定了浅蓝底。
- 条数多了以后，和这位学生关系不大的默认收起（见下面「收起关系不大的」），列表下面一行「另有 N 条和你关系不大，已收起」，点「展开」还在，字淡一档。样子见 `计划/通知-收起关系不大的.jpg`。
- 和作业一样先画缓存、后台再读。读成功后十分钟内再进页面不重读；读失败后五分钟内不自动重试；页面右上角的刷新两栏一起读，不受限制。这次没读到时原来的留着，列表下面说明原因。
- 「校园通知」插件关着、统一身份认证或 WebVPN 还没填时不读学校通知，列表下面给一个去插件页的入口；公众号插件关着时不显示公众号文章。
- 「交给助手」开一个新对话，把标题、来源、日期和原文链接写进输入框，请助手读全文后说和用户有没有关系、要做什么、什么时候截止。

还没做的：钉钉、学在浙大的课程公告、CC98 消息没有接进这一栏；侧栏上没有未读数，也没有系统弹窗。点一行是在应用自己的阅读窗口里打开原文，复用应用存着的统一身份认证和 WebVPN 会话，见「看网页的窗口」一节。

### 收起关系不大的

2026-10-12 加的，用户要的：一周内的通知就有五十多条，加上公众号的文章更多，其中大半不是给学生看的。拿用户当时缓存里的 53 条数过：劳务派遣和各类招聘 16 条、会计核算中心经费认领 3 条、科研院项目申报 4 条、教职工培训和校务 5 条、研究生和博士生的 3 条、毕业生的 2 条、别的校区停水 1 条，合起来三十多条和一个 2025 级的本科生没关系。

两道（`ui/profile/notice-filter.mjs`），都只是收起，不删：

- **屏蔽词**：标题里有就直接收起，不用问模型。一开始带三个：劳务派遣、经费认领、汇款认领（用户点名要的是「劳务派遣」）。只放不会误伤的，「招聘」就不行，校园招聘会也带这个词。
- **模型照个人档案判断**：剩下的连同基础信息（培养层次、学院、专业、入学年份、校区，称呼不给）交给模型，一条条判断和这位学生有没有关系。提示里写明：面向教职工和科研人员的、只面向别的培养层次的、只针对别的学院或校区的、只和别的年级有关的算无关；拿不准的算有关；公众号的文章是他自己订阅的，只有明显和学生无关才算无关。一条只问一次，结果存在 `cache\relevance.json`；基础信息变了就全部重问。记忆里的兴趣和目标这一轮没有用。

问模型走的是引擎的模型服务（`ui/profile/model.mjs`，做法照引擎给对话起标题的那个包），用的是用户现在选的那个模型，DeepSeek Key 和 ChatGPT 登录都行，不另要 Key。一次问四十条，一轮最多三次，新的先问；问不成就不筛、照原样全给，十分钟以后再问，上一次没问成的原因记在 `relevance.json` 里。问的时机是页面那一趟「读新的」的最后（`feed.mjs` 的 `refresh`）：读完学校的新通知、点刷新时催完公众号以后，把还没问过的问一遍再把结果给页面，所以页面先照缓存画，过一会儿换成筛过的。

踩过的一处：DeepSeek 默认想得很深，筛四十条光思考就把 4000 个 token 用完了，一个字没答（引擎报 `max-tokens`）。现在问的时候带 `reasoningEffort: 'low'`，上限放到 8000；这一家模型不认这个写法或者这样没答成，就照它默认的再问一次。

屏蔽词和要不要让模型判断在「校园通知」的详情页里改（`ui/client/NoticeFilterSettings.tsx`，存在档案目录的 `notices.json`），样子见 `计划/校园通知-屏蔽词.jpg`。

验证：`ui/profile/notice-filter.test.mjs` 四项（屏蔽词、只给模型看要用的几项、一条只问一次和基础信息变了重问、问不成和分批）、`feed.test.mjs` 一项、`host.test.mjs` 里读写设置。2026-10-12 用真的模型跑过一遍：只起引擎，放进用户当时缓存里的 53 条通知和三篇公众号文章的副本，基础信息是本科、计算机学院、2025 级、紫金港。56 条里屏蔽词收起 16 条，模型收起 17 条（毕业生的两条、科研院的四条、别的校区停水、教职工培训、博士生和研究生代表大会、研究生评奖、三条招聘启事、敬老月等），剩 23 条，用了 20 秒。「校领导接待群众来访」这种留下了，照的是拿不准算有关。没验证的：登录的是 ChatGPT 账号时的模型调用；新通知陆续到的时候一条条增量地问。

### 备忘录（左栏下面）

用户自己记的一件件事（`ui/client/Memos.tsx`）。栏里做得简单：标题那一行右边是「新建」，下面一行一条（标题和最近改动的日期），先露出五条；有归档的时多一个「备忘 / 已归档」的切换。没有搜索、标签筛选和导入，这些只留给设置里的记忆。点开一条是整页的单条，再进编辑，界面和记忆是同一套；办完的归档，不要的删除。

助手这边有 `campus_note_read` 和 `campus_note_write`：用户让它记一件事时才写，问到记过的事时才查；备忘录不进每次对话的上下文。助手按用户说的新记的一条，没人动过时它可以重写；用户自己写的或改过的，它只能在后面补充。

- 左栏是章节目录：一个大章一块，标题条点一下展开或收起，下面是各节，一节一行、行间一根细线，每行右边写有几个课件、几个视频；点中的那一节是引擎那种浅底色、字加粗。「资料」栏的文件夹是最后一块。没有分大章的课，各节合成一块、没有标题条。目录放在定高的框里滚动，滚动条的位置一直留着（展开以后长出框外时，行右边的字不会被挤着挪）。
- 块的样子和智云那一边学在浙大的章是同一种（`style.css` 的 `.campus-learn-chapter`：带细边的圆角框，很淡的灰色标题条，里面的行是常规粗细），2026-10-11 跟着学在浙大那一边改的。10-10 的第一版是照引擎侧栏排的目录（一行 32px，大章和各节同一种字）；用户先说这边的字看着比智云小一号（两边字号一样，差在粗细），学在浙大那一边改成块以后问超星这一边，就一起换了，两边看着是一套东西。
- 目录最上面多一组「我的实验」：本人实验课表（`lab timetable`）上的实验对到这门课的哪一节，按上课的先后排，行右边是哪天上。课表读不了（「课程与作业」关着、实验课的密码没填）、读不到、一个也对不上时没有这一组，不报错。课表和学习通的叫法不完全一样，对法照 core 里 `chaoxing --chapter` 的规矩（`chaoxing.mjs` 的 `matchTitle`）；两周连做的写成「组合1：▲甲实验+乙实验（2周）」，拆开各对各的（`matchTitles`）。用户的真实课表 14 次课、12 个不同的名字，对到了 13 节。
- 进页面时替用户点好一节：有课表时是接下来要上的那个实验（都上完了是最后一个），没有课表时是第一节。
- 右栏是点中那一节的文件：最上面是这一节的名字和它在哪个大章里（是自己要上的实验时带上哪天上），下面一根细线；再下面「课件」「视频」各一块（和左栏一样的块，标题条不能点），一个文件一行：文件类型的图标、名字、大小，行尾一个小图标下载，下过的变成打开文件夹的图标。没有的那一块里写「这一节没有视频」。老师没开放下载的写明，不给按钮。点别的一节时右栏带动效换（旧的淡出，新的升上来）。
- 这一节有视频时，右栏最上面那一行的右边选清晰度（和智云那一边「智云 / 学在浙大」的切换是同一个位置；原来在「视频」标题的右边）：「原画」是老师上传的原文件，「流畅」是平台的播放版（720p 左右，体积约十分之一）。选了哪个记在浏览器的 `campus.learnVideoQuality`。两种分开存、分开记，各有各的「已下载」。播放版事先不知道多大，不写大小。
- 这一边没有总结和讲解，也没有「全部下载」。

文件落在 `文档\CampusAgent\课程\<课程名>\<章节>\<小节>\`，和智云的课次文件夹在同一个「课程」下面（同名的课会在同一个文件夹里；智云那一边只认带 `download.json` 的课次文件夹，互不影响）。具体位置由 core 定，下完它会说；`chaoxing.mjs` 把路径记在缓存的 `saved` 里，凭它认「已下载」，文件被挪走了就当作没下过。助手自己用技能下的（默认在 `data/output/chaoxing`）页面不认；在页面上再点一次会下到「文档」里。

读取：课程表进页面就读（`chaoxing course list`，十分钟内不重读，失败后五分钟内不自动重试，也不马上重试，免得密码错时反复登录招来验证码）；接着整门课的文件一次读回来（`chaoxing chapter list`，要一节一节地读，三十节约十秒），页面上点哪一节都不用再等；实验课表同时读。这两样半小时内不重读（core 自己也把清单留半小时），点刷新时都重读，`chapter list` 带 `--fresh`。交给 core 指一门课的是 `course list` 给的课程链接，不是名字（名字会重、会互相包含）。下载是 `chaoxing material|video download --course=链接 --chapter=这一节的位置 --name=文件名 [--quality=playback] --out-dir=课程文件夹`。缓存在 `%APPDATA%\CampusAgent\cache\chaoxing.json`。「学习资料」插件关着、超星学习通的账号没填时不读，目录下面给去插件页的入口。为这一页在 core 里加的东西见 `core/zju/lib/chaoxing/README.md` 开头。

验证：`npm run test:profile`（含 `chaoxing.test.mjs` 九项：列表、缓存和不重试、开关和换账号、一门课的各节、实验名怎么对、我的实验、下载和两种清晰度、下载进度、下不了的几种）。页面在隔离实例里用假的 core 点过（第一次读、目录展开和点一节、下载中、下完、换清晰度、下不了、老师没开放、多门课的下拉、没有大章的课、深色、窄窗口），量过展开目录、换一节前后切换、刷新、目录行右边的字、右栏按钮的位置都不变。引擎侧这条链路用用户真实的账号只读地跑过一遍（1 门课、34 节、51 个课件、24 个视频，课表对到 13 节）。没验证的：没有在页面上用真实账号实际下过文件；「流畅」这一种没有对着真实平台下过。

### 下载进度

2026-10-10 加的（用户要的：大文件下载要有进度）。智云一次课的资料、超星的文件和学在浙大的课件（2026-10-11）都有：下的时候那一行右边写百分之几，行的底边上有一根线从左往右长；线压在行与行之间那根细线的位置，不占高度，出现和消失时别的行不跳。没下完之前最多写到 99。

- core：下载器（`core/zju/lib/zhiyun/download.ts` 的 `Transfer`，智云、超星、学在的下载都走它）记着已经收到多少字节和一共多少，`ZJU_PROGRESS=1` 时每 200 毫秒往 stderr 写一行 `[zju:progress] {"bytes":…,"total":…}`。一个文件的总量就是它的大小；一批差不多大的文件（HLS 的分片、一张张课堂截图）事先报个数（`plan`），没开始的按已知的平均大小估。续传时已有的块算作已经收到，重试的那一段会退回去重算。不设这个环境变量时一行也不写，助手自己跑命令时看不到这些行。
- 引擎侧：`runCore` 给了 `onProgress` 就设这个变量并读 stderr（`ui/profile/core.mjs`）；`learning.mjs` 和 `chaoxing.mjs` 各记着正在下的那几项下到哪了，`learning-downloading`、`chaoxing-downloading` 两个接口只看内存。
- 页面：有一行在下的时候每半秒问一次（`learnParts.tsx` 的 `useDownloading`）；回来的结果里少了一项就是它下完了或者没下成，页面重读。所以下载途中离开这一页再回来，进度接着走，下完了也知道。百分数只升不降（分片的回放总量是估的，会来回晃）。

验证：core 的上报用本机起的一个小 HTTP 服务核对过（分块下载、不支持 Range 的整文件、事先报了个数的一批小文件：总量都对、只升不降、文件完整；不设变量时零行）；两边的引擎侧各有一条测试；页面在隔离实例里看过（行高和按钮的位置在下载前后不变）。没验证的：真实的大文件、真实的 HLS 回放。

## 校园插件

插件页由 `ui/client/PluginsPage.tsx` 提供，结构照引擎自带的插件页：列表里一行一个插件（图标、名字、一句话、右边的开关），点进去是详情页（顶上返回，图标和开关，名字和一行说明，接着按系统逐条列它能做什么，下面是账号表单）。每个校园功能的一行说明（`description`，要短，只说接了哪些系统）和按系统列的内容（`systems`）都写在 `ui/profile/catalog.mjs`。列表默认排两列，右上角可以切成单列，选择记在浏览器的 `campus.pluginColumns`；主区域不到 680px 宽时自动收成一列。校园功能的名字、说明、功能、对应的模块和账号都在 `ui/profile/catalog.mjs`；通用工具的在 `ui/client/pluginCatalog.ts`。

校园功能有六项：校园账号、课程与作业、校园通知、活动与场馆、学习资料、校园社区，全部是 ZJU Core 的功能，合起来覆盖它除读文档以外的所有模块（读文档各项都要用，始终可用）。校园账号是各项共用的基础，没有开关；其余五项可以单独关掉。开关存在档案目录的 `plugins.json`，由 `ui/profile/plugins.mjs` 管，关掉一项有两个效果：

- 对应的 ZJU Core 模块写进 `ZJU_DISABLED_MODULES`（core 自带的禁用开关），引擎之后启动的命令会被 core 自己拒绝，报「模块已被当前运行环境禁用」。启动环境里原有的禁用项保留。已经开着的常驻终端要等下一个命令进程才生效。
- 模型上下文里多一句说明，告诉它哪些功能被关了、不要去调。

哪一项对应哪些模块写在 `ui/profile/catalog.mjs` 的 `CAMPUS_PLUGINS`。点开关时只有被点的那一个变，页面先按点下去的状态显示，保存失败再退回去。

「课程讲解」（2026-10-11 加的，用户要的：Learning 技能单独做成一个插件，开了以后下面能装依赖）排在校园功能的后面，和微信公众号一样不是 ZJU Core 的功能，登记在 `catalog.mjs` 的 `LOCAL_PLUGINS`（`backend: 'learn'`）。**它默认关着，要用户自己打开**（接入表里的 `optIn`，同一天用户定的；别的插件都默认开着）：做一份讲解很花时间和模型用量，不替人开。为这个，`plugins.json` 里多了一张单子：`disabled` 记默认开着而被关掉的，`enabled` 记默认关着而被打开的；`plugins.mjs` 对外仍然只给一张「现在关着的」，用的地方不用管哪一项默认是什么。加这一项以前存下的 `plugins.json` 照旧能读，升级上来的人「课程讲解」是关着的。关着时：

- `learn` 技能不再交给引擎（`skills.mjs` 按开关过滤，开关一变就叫引擎重读技能目录），助手的技能目录和输入框的 `/` 菜单里没有它；
- 模型上下文里说明它关着（用户没打开过也说，这样有人要讲解时助手会请他去插件页打开，不会自己拼一个出来），也不再提讲解目录；
- 学习页一次课的「讲解」那一块不给「让助手讲这次课」，换成一句去插件页打开的入口；做好的讲解照常能放。

开着时详情页多一组「可选依赖」（`ui/client/LearnSettings.tsx`，引擎侧 `ui/profile/learn.mjs`），一行一样：名字、它是什么、装没装。没有它们讲解也做得出来。

- **公式排版**：TeX（`latex` 和 `dvisvgm`）。讲解打包时用它把公式排成字形轮廓，没有时由播放器里的后备排版来画（`core/learn/engine/tex.mjs`）。本机已经有 TeX 的（照引擎的找法：`LEARN_TEX_BIN`、`PATH`、`E:\texlive`）显示「本机已有」；没有的给一个「安装」。点了以后在后台装，页面每秒读一次装到哪了，离开这一页再回来接着显示；应用自己装的那一份可以「卸载」（删掉那个文件夹）。
- **版面检查**：本机的 Edge 或 Chrome，助手做讲解时用它无界面地打开成品自查和截图（`engine/lint.mjs`、`shots.mjs`）。Windows 自带 Edge，这里只看有没有，不管装。

TeX 的装法：从国内的 CTAN 镜像（浙大、清华、中科大，最后是 CTAN 的总入口，哪个先连上用哪个）取 TeX Live 的安装程序，按一份写好的清单装最小的一套（只有安装器本身、基础和 LaTeX 两组包，不装文档和源码），再用它自己的 `tlmgr` 加上 `dvisvgm`。装成便携的：不改系统的 PATH、注册表和开始菜单。位置是数据目录下的 `tools\texlive`（`%APPDATA%\CampusAgent\tools\texlive`）；TeX Live 装不进带中文或空格的路径，用户名带这些字符时改放 `C:\ProgramData\CampusAgent\texlive`。装好以后把它的程序目录放进环境变量 `LEARN_TEX_BIN`，引擎之后启动的命令都会继承；用户自己设的 `LEARN_TEX_BIN` 在没装我们这一份时原样留着。

真装的时候碰到、已经处理的三件事：解安装程序要用系统自带的 `tar`（写的是 `System32\tar.exe` 的全路径；PATH 上排在前面的可能是 Git 带的那个，它把 `C:` 当远程主机）；安装程序自己下包用的 curl 没有防停住的参数，经本机代理去连校内镜像时下到一半停住不动过，所以给安装程序的环境里去掉了代理的设置（它直连镜像，和我们取安装程序走同一条路），并换成带「三十秒里每秒不到 4 KB 就算断了、断了重试」的 curl 参数（`TEXLIVE_DOWNLOAD_PROGRAM`、`TEXLIVE_DOWNLOAD_ARGS`）；安装程序开头先装它自己用的几个小包，那一轮的「第几个 / 共几个」不算进度，不然进度会先冲到头再退回来。

验证：`ui/profile/learn.test.mjs` 四项（装在哪、怎么认本机已有的和自己装的、安装的每一步和进度、没装成时不留半截）。在开发机上往临时目录真装过一遍：7 分钟，装完 221 MB，状态变成「已安装」、`LEARN_TEX_BIN` 指过去；用这一份经引擎的 `tex.mjs` 排了六条公式（分式、求和、`\mathbb`、矩阵、积分），缓存目录放在带中文和空格的路径下，六条都排出来了。详情页在隔离实例里看过（开发机上本来就有 TeX，显示的是「本机已有」）。**没验证的：页面上点「安装」到装完这一整趟**（只测了引擎侧的安装和页面的显示，没有在一台没有 TeX 的机器上点过）；用户名带中文时改放 `ProgramData` 的那条路只有单元测试；校外的网络上要多久。

没放进来的一样：

- **配音**（用户举的例子里有它）。讲解的配音是 IndexTTS：要 NVIDIA 显卡、Python 环境和十几 GB 的模型，而且应用里播放讲解的窗口（`desktop/film.cjs`）只是把成品打开，不会去叫配音服务，装了也出不了声。要做的话先得让播放窗口会放配音，再谈安装，是单独的一件事。

第三组「技能」是助手学到的做法（`ui/client/Skills.tsx`，引擎侧 `ui/profile/learned.mjs`），没有开关，样子见 `计划/插件页-技能.png`。一件校园事务助手经过多步探索才走通之后，用 `campus_skill_save` 把最短的走法存下来：英文短名（引擎只认小写字母、数字和短横线的名字）、给人看的名字、什么时候用、正文。一个技能是档案目录 `skills/` 里的一个 Markdown 文件，格式就是引擎的技能文件，和应用自带的几个技能一起交给引擎，所以它会出现在模型的技能目录和输入框的 `/` 菜单里，存下以后同一个对话里就能用。列表里一行一个（图标用引擎给没有图标的插件的那一个），点进去看全文，右上角可以删；只有人能删。原来的做法是让助手往 `core/zju/flows/` 里写文件，那是应用的安装目录，页面上看不到，重装就没了；现在 `flows/` 只放开发整理过的工作流。

通用工具只展示网页搜索、自动化任务、自动授权审查和语音输入，后三项的开关就是引擎里对应包的开关。终端、Agent 循环、子智能体的设置入口隐藏，底层能力保留；智能体团队不在产品插件页展示。搜索和语音沿用引擎原生配置组件，自动授权审查仍需要用户在对话权限里选择相应模式。

`desktop/profile.mjs` 初始化校园 profile，并在首次应用校园默认值时加入自动化 Bundle；`campus-defaults.json` 记录默认值已应用。后续用户手动关闭自动化，重启不会重新开启。当前机器和新安装均采用此规则。

账号和密码都在插件详情页里填，每个插件只放自己用的：「校园账号」里是统一认证、WebVPN 和校内网站的访问方式；「课程与作业」里是 PTA 和实验课平台；「活动与场馆」里是校园卡查询密码和场馆同伴的账号；「学习资料」里是超星；「校园社区」里是 CC98。详情页里不放去别的页面的跳转（学院和专业在设置的个人档案里自己填）。密码直接显示在输入框里，默认遮住，点右边的眼睛才显示；清空一项再保存就是删掉它。CC98 可以填好几个账号：默认一个，下面有「添加另一个账号」，点一下多出一组，追加的每组右边有「移除」；第二个起存成 `cc98_username_2` / `cc98_password_2` 这样带序号的键，和 ZJU Core 认的写法一致，最多九个。保存写进 `accounts.json`（`ui/profile/account.mjs`），带版本检查，别处改过要先重新读取；页面上没有的键（第二位场馆同伴，键名带 `_2` 后缀）原样保留。账号只走这一条路：不进个人档案，不进模型上下文，档案工具也读不到。缺了必填账号的插件在列表上带「待填写」「待填账号」的标记。

验证命令：`npm run test:plugins`、`npm run test:profile`、`npm run test:trace`、`npm run typecheck`、`npm run typecheck:core`。

`ui/profile/store.mjs` 是基础信息、记忆和备忘的存储实现：记忆和备忘各是档案目录里的一个文件夹，读写规则是同一套（文件里的 `Shelf`）。界面走引擎已认证的 `/api/campus/profile`，备忘录的操作名前面带 `memo-`；AI 读写记忆用 `campus_profile_read` 和 `campus_profile_write`，读写备忘用 `campus_note_read` 和 `campus_note_write`。

模型上下文只包含基础信息和前 50 条记忆的目录（标题、标签、属性），全文按需读取；备忘录不进上下文。记忆怎么写在 `campus_profile_write` 的说明里：一个主题一条，标题就是主题；学期、来源放属性，正文不重复；正文先一两句话说清楚，再分小标题列要点，写事实，不写给模型的指令；提到另一条记忆用双链。记忆、备忘录、技能三样各在什么时候写，写在助手的底层说明 `core/AGENT.md` 的「留下来的资料」一节。AI 自动写入依赖模型按这些规则调用工具，不对每个校园查询结果机械记一条。

### 半小时看一遍，新文章进通知

这是这个插件最要紧的用处（用户 2026-10-12 说清楚的）：像订阅 RSS 一样定时去看，新文章自己出现在「校园事务」的通知里。体艺类的公众号常发要报名的活动，不常翻公众号的人靠这个不会错过。不是让助手去盯，所以详情页原来通到「自动化任务」的那一行去掉了，助手的说明里也写明不用它定时去查。

应用开着时每分钟看一眼到没到点（`wechat.mjs` 的 `tick`），半小时检查一遍（`CHECK_MS`，间隔是用户定的）：对一遍跟踪名单，看一眼微信读书的登录状态，再读一遍文章。技能自己先看本机微信（不联网，读的是电脑版微信已经收到的推送），本机没有的号再问微信读书，号与号之间隔一秒半。除此之外只有用户动手时才检查：加了一个号、登录了微信读书、改了下面的开关、在详情页点了「去验证」，或者在「校园事务」页点了刷新。打开详情页不读文章。

后台的检查带 `WEREAD_INTERACTIVE=0`，不开窗口。微信读书要验证时，「自动识别验证码」开着就在隐藏的窗口里自己过；关着，或者登录过期了，技能返回 `verification_required`、`login_required`，这时停下不再问微信读书，记在缓存里，详情页那一行给「去验证」「重新登录」，通知下面也有一句。用户把「自动识别验证码」打开，等着的那一次马上重试。被限频的等两个小时自己再试。

一个号第一次读到的文章不算新出现的（`foundAt` 是空的），之后多出来的才记下发现的时间，通知那一栏靠它在标题前画点。两个来源给文章编的号不一样，一个号换了来源就把它那一份整个换掉，免得同一篇出现两次。

没做系统通知（托盘弹窗）：新文章只是出现在通知里。

### 把链接交给助手就能读

公众号文章的链接直接去抓会被验证拦住，或者要一个真的浏览器。走这个插件就读得到：`weread` 技能的说明第一句和 `core/AGENT.md` 都写明，用户给了 `mp.weixin.qq.com` 的链接就用它的 `read --url`，不要先试别的办法。通知里每一条的「交给助手」带的也是原文链接。
