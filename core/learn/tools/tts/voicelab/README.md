# 做一个音色

你给音频，我来调，调好了朗读器里就能选。这份文档定三件事：音频放哪，我按什么步骤调，怎么进朗读器。

## 目录

```
voices\<音色名>\
  data\             你给的原件，原样放着，只读。音频、视频、台词文本都行，可以分子文件夹
  candidates\       从 data 里切出来的候选参考句，一句一个 wav，已经调到同样的响度
  trials\           每个候选试克隆出来的样句（<候选>\<语言>-<序号>.wav）和分数表 scores.tsv
  voice.wav         定下来的参考句。有它，这个文件夹才算一个音色，朗读器只认它
  voiceprint.npy    这个人的声纹，量"像不像"用的参照
  notes.md          这个音色的记录：素材哪来的，试过哪些，为什么选了这一句，你听后怎么说
```

和讲解的目录是同一条规矩：你给的东西放 `data`，别的都是做出来的，删了可以重做。文件夹的名字就是朗读器下拉框里显示的名字。

## 调的是什么

IndexTTS 是零样本克隆：给它一段参考音频，它照着这段的音色、语速、停顿、情绪去读新的句子，连背景音乐也会学进去。它没有可以训练的权重，官方没有放训练代码，所以这里没有"训练"和"微调"，能调的只有一样：**拿哪一句当参考**。实测下来也是这样，相似度几乎只取决于参考句选得好不好：

- 一句连续的自然语音，好于几个片段拼起来的。
- 说得平稳连贯的句子，好于害羞、迟疑、情绪重的句子。后者克隆出来又慢又断。
- 每句多合成几遍挑最像的，6 选 1 只比平均高 0.02；调采样温度没有可见效果。这两样不用试。

所以流程就是：从素材里切出候选，让每个候选读同一组测试句，量一量，听一听，定一句。

### 当前选材偏好（2026-10-07）

用户明确不喜欢慢速、舒缓、端庄独白和耳边细语。优先找剧情中正常音量、正常语速的交流、解释和讨论，保留自然的语调变化。生日祝福、亲密倾诉、助眠、耳语和刻意放轻声音的片段不作为默认参考；“背景安静”不等于“说话很轻”。先判断整段听感和连贯程度，再比较声纹分数，不因声音温柔或相似度更高而优先选用。

新增或重选音色时必须查剧情对白来源，不能只收角色资料页的“心声、关于某人、生日祝福”。视频标题写“干声”不代表无损或未经分离，要核实来源和音质。剧情录像总时长也不能算成该角色的独立语音时长。没有找到合格剧情原声时，明确记录缺口，不把资料语音或 AI 二创当成已经补齐的剧情素材。

候选不局限于《鸣潮》。用户认为烟绯、铃、能天使等上一轮候选对他太冷门，后续优先他熟悉、辨识度高的角色；目前优先比较芙宁娜、胡桃、三月七，同时坚持正常音量与连贯剧情对白的要求。爱弥斯、千咲、清宵保留为此前查源记录。守岸人和心月狐已按用户要求移除，不重新建立这两个音色，除非用户另行要求。

## 流程

| 步 | 做什么 | 命令 | 产物 |
|---|---|---|---|
| 1 收 | 你把音频放进 `data` | | `data\` |
| 2 切 | 切出背景干净、一句一句的人声 | `tts harvest`（游戏语音包用 `tts pick`） | `candidates\` |
| 3 量 | 算出这个人的声纹，剔掉不是他的 | `tts similar … --save` | `voiceprint.npy` |
| 4 挑 | 留下几句适合当参考的 | | `candidates\` 里剩下的 |
| 5 试 | 每个候选读同一组测试句 | `tts trial` | `trials\` |
| 6 定 | 选一句，记下来 | | `voice.wav`、`notes.md` |
| 7 进朗读器 | 不用做，自动出现 | | |
| 8 听 | 你听，说哪里不对，我回到第 4 步 | | `notes.md` 里添一条 |

第 2 到第 7 步我一口气做完，不停下来等确认。第 8 步只有你能做。

**1 收。** 新建 `voices\<名字>\data\`，把音频放进去。在对话里直接给我文件路径也行，我复制一份进 `data`，你的原件不动。什么样的素材好用：

- 只有这一个人在说话，没有背景音乐。一直垫着音乐的素材用不了。
- 至少有一句 7 秒以上、一口气说下来的话。总共有一两分钟更好，可挑的多。
- 语气接近讲课：平稳、连贯。撒娇、耳语、喊叫、边笑边说的句子不要。
- 格式随意：wav、mp3、m4a、ogg、flac 都行；录屏和视频（mp4、mkv、webm）也行，取的是音轨。
- 微信语音这类导不出来的，可以录屏。提示音和别人的声音会一起录进去，第 3 步会剔。

素材是真人（同学、家人）的声音时，先得到本人同意。做出来的音色只在本机自己听。

**2 切。**

```powershell
.\tts harvest voices\<名字>\data --out voices\<名字>
```

把直接放在 `data` 下的每个文件切成一句一句（子文件夹不会自动进去，要切就把子文件夹的路径单独写一次）：只留背景安静时的人声，停顿不到 1 秒的相邻短句连成一句，超过 13 秒的在最长的停顿处断开，每句调到同样的响度。输出里有每句的秒数和停顿占比。录音有底噪、一句也切不出来时加 `--bed -50`。

**3 量。**

```powershell
.\tts similar voices\<名字>\candidates --save voices\<名字>\voiceprint.npy
```

它列出每一句和其余各句有多像，从最不像的排起。排在最前面、明显掉队的，是别的说话人、提示音、音效，或者情绪很重的句子：从 `candidates` 里删掉（候选是做出来的，可以删；`data` 不动），再跑一次，这次存下的才是他的声纹。输出的"真人自己和自己"是这批素材的天花板，克隆的分数到了这个范围就到头了。

**4 挑。** 留下 4 到 8 句送去试：7 到 13 秒，停顿占比低（一成半以内），语气平稳。最要紧的是连贯：中间没有明显停顿、一口气说下来的句子排在前面，哪怕短一点、相似度低一点。这个人的素材里凑不出这样的长句时，不要拿停顿多的句子充数，用第 2 步的 `--gap 0.5 --min-seconds 5` 专门切连贯的片段。其余的删掉。素材里没有 7 秒以上的连贯句，就用 `tts voice` 把最像的几个短片段拼成一条，当一个候选一起试：

```powershell
.\tts voice voices\<名字>\candidates --out voices\<名字>\candidates\joined.wav
```

**5 试。** 先关掉朗读器。

```powershell
.\tts trial <名字>              # 配音用英语时加 --lang en
```

每个候选读 `sentences.json` 里固定的三句讲课的话，样句存进 `trials\`，分数记进 `trials\scores.tsv`：相似度、语速，样句的谐噪比（嗓音虚不虚）和齿音（s、sh 这类音比元音响多少），还有几句里有几句开口前先吐了一口气、几句没说完被掐了尾。只想补试某几个候选，就把文件名写在后面。

**6 定。** 看分数表，按下面"怎么判断"选一句，复制成 `voice.wav`，然后写 `notes.md`。

**7 进朗读器。** 不用做任何事。朗读器每两秒看一次 `voices\`，带 `voice.wav` 的文件夹会出现在顶栏的音色下拉框里，朗读器开着也会出现。讲解、`tts say`、`tts synth` 都用文件夹的名字指这个音色。两点要知道：

- 换掉一个已有音色的 `voice.wav` 之后，重开一次朗读器。它是在选中音色的那一刻认参考句的，开着的时候换文件它不知道。
- 默认音色写在 `tools\tts\engine.py` 的 `DEFAULT_VOICE`，你说要换默认我再改。

**8 听。** 我听不见声音，分数只管这几件事：音色像不像，语速正不正常，嗓音虚不虚，齿音冲不冲，句首吐不吐气，句尾掐没掐。自然不自然、语气对不对、有没有杂音，要靠你的耳朵。定完之后我给前两三名各合成一段半分钟左右的话，连同各自的原声一起放进 `out\试听\<名字>\`，你对着听；也可以在朗读器里选这个音色放一段讲解。给你听的样句要够长，并且只用你打算用的那种语言：试克隆用的测试句每句只有三四秒，是给我量分数用的，拿来听是听不出像不像的。不满意就告诉我哪里不对（太慢、太尖、像在撒娇、有电流声），我回到第 4 步换一句，把你的话记进 `notes.md`。

## 怎么判断

这部分是我调的时候看什么、怎么取舍。

- **语速跟着参考句走，挑参考句先量它自己说得多快。** 克隆出来每秒几个字，和参考句每秒几个字几乎一样（心月狐：参考句 3.2，读讲解 3.6；换一句 4.8 的，读讲解 4.7）。游戏里的"个性语音"（心声、关于某人、生日祝福）是对着玩家慢慢说的独白，整体偏慢、停顿长，拿来读讲解像小心翼翼地念；用户 2026-10-05 的原话是"语速特别慢，都是那种像小心翼翼地读一样的感觉。感觉是因为你选的句子都是那种很端庄的场景"。所以切出候选之后，先数每段的音节算出每秒几个字（响度包络上的峰，和真字数比只少数 6%），从快的、停顿短的里面挑；中文讲解的目标是连停顿每秒 4.7 个字上下。整套素材都慢、最快的几段也不到 4.3 的（守岸人），换参考句没有用，在 `voice.json` 里写 `speed`（0.85 到 0.9），或者去找这个角色说话快的素材（剧情对话）。中文的语速以前没有基准、一直没量，这个坑是这么来的；现在 `sentences.json` 里中文三句按每秒 4.8 个字记了基准。
- **先看语速，再看相似度。** 只看相似度会选出"像但是拖沓"的参考句：从视频里切出来拼的那一版，相似度不低，语速慢了四成。语速在 1.2 以上的候选不要。
- **相似度差 0.02 以内算一样。** 同一句多合成几遍，分数的波动就有这么大。这时选语气最接近讲课的那一句。
- **到了天花板就停。** 克隆的相似度进了"真人自己和自己"的四分位范围，再换参考句也不会更像。
- **全都明显低于真人自己的范围**，问题在素材：底噪、混响、垫乐，或者候选里混着别人。回到第 2、3 步重新切和剔。还不行，就告诉你缺什么样的素材，请你补。
- **像，但是又慢又断**，是参考句本身说得慢、停顿多。换一句说得连贯的。反过来不成立：参考句停顿多，克隆出来不一定慢（结灯的候选停顿占 15% 到 20%，克隆的语速却和咲来一样），所以别凭参考句的样子猜，试了再说。
- **音色对，但一停一停的不顺**，是克隆把参考句的停顿方式学过去了，说明当初挑的句子就不对。回去挑本来就一口气说下来的句子：`tts harvest … --gap 0.5 --min-seconds 5` 只切中间没有明显停顿的片段。这样的片段往往只有五六秒，相似度的分数会比带停顿的长句低一点，但克隆出来顺。不要去剪参考句里的停顿：试过把每处停顿剪到 0.15 秒，克隆的停顿确实少了，用户一听说"整个人说话感觉很急促"，否掉了。
- **连贯比分数重要。** 挑候选时先看是不是一口气说下来的，再看相似度。爱弥斯那次，用户从三组里听出来最像的那一句，正好是她全部素材里最长的一段没有停顿的话（9.9 秒），而它的分数并不是最高的。（这一句后来因为太轻换掉了，见下面"像说悄悄话"那一条：连贯和像都只是必要条件。）
- **克隆出来沙沙的**，是参考句本身带气声。轻声细语的句子嗓音里气声多，克隆会整段学过去。用谐噪比量：正常说话在 9 分贝上下，带气声的只有两三。`pick` 现在会量每句的谐噪比，比这个人一般的句子低 2 分贝以上的不要。要当心的是，有的角色只有在轻声说话时才不停顿（守岸人就是：剧情里连贯的 20 句没有一句嗓音是清楚的），只按"连贯"去挑，挑到的全是气声。这时宁可用短一点、但嗓音清楚的连贯片段。
- **读起来小心翼翼、像说悄悄话，齿音"呲呲"的**，是参考句挑到了这个人说得最轻的一段。爱弥斯就是：用户挑的那句最像，也是她音高最低、最轻的一段，用了一天就听出来了。轻声说话时元音弱下去、齿音不弱，所以看两个数：样句的谐噪比在这个音色的候选里垫底，齿音和元音差不多响（0 分贝上下，平常在 -2 到 -4）。这两样要量克隆出来的样句：那句参考句自己的谐噪比是候选里最高的，读出来却最虚。`trial` 的三句测试句太短，这两列只能筛掉明显差的；要定的时候，让前几名各读一段四十秒的话再量。换成她平常音高、嗓音清楚的一句就好了，齿音的尖刺也少了三成。齿音本身是录音里就有的（鸣潮的官方录音齿音都亮），没有齿音的句子里一处尖刺也没有；没有去削它，削高频用户说过不像。
- **句子之间有电流声、爆破声**，是模型在每句话前面先吐了一口气（见主 README 的"句首的气声"）。这是跟着参考句来的：咲来的 12 个候选各读 3 句，有的 3 句都有，有的一句没有（08、10）；再各读 10 句日语，现用的 03 是 10 句都有，08 是 0 句，10 是 3 句；结灯也是一半候选有；爱弥斯、心月狐、守岸人几乎没有。它和参考句里喘不喘气、怎么开头结尾都对不上，只能看 `trial` 的"气声"一列。`engine.breath` 会把它切掉，但挑参考句时仍然优先挑不吐气的：切不掉的短气声只能靠淡入盖一盖。三句太少，定之前让前几名各读一段四十秒的话再数。用户另外报过读讲解时句子中间的爆破声（USB 声卡，倍速 1）：在他听的那批缓存音频里查过冲击、削顶、句首句尾，没有找到；要他指出具体哪一句哪个字再查，不凭猜去改。
- **参考句的长短影响很小。** 做过对照：同一条参考句只取开头 3、5、7、10 秒去克隆同一段话，相似度都在 0.84 到 0.88 之间，差别不超过同一条参考句合成两遍的波动。所以 5 秒和 7 秒的参考句不用按长短取舍，看的是这几秒里的声音好不好：清楚、连贯、语气对。
- **候选只有一两句**，直接试，把结果和"素材太少"记进 `notes.md`，告诉你再给哪种素材会更好。
- **参考句的语言和配音的语言保持一致。** 这是用户的明确偏好：中文原声读中文，英文原声读英文，日语原声读日语；不因模型支持跨语言就混用。测试句使用对应语言。

## 不能破的规矩

- **定哪一句靠听，不做自动调音。** 不做自动选优的页面或脚本，`tts trial` 只量不选；分数不当结论，定之前先让用户听。
- **`data` 只读。** 不改，不删，不往里写做出来的东西。
- **一次只开一份模型。** 试克隆之前关掉朗读器：显存只够开一份（一份常驻约 7GB）。`tts trial` 发现朗读器开着会直接退出。系统内存的余量不用手动看，`engine.load` 会自己把页面文件扩出来，见主 README 的"系统提交内存"一节；它报内存不够时才需要关程序。
- **一把尺量到底。** 所有音色都用 `sentences.json` 里那几句、用各自的 `voiceprint.npy` 量。测试句不要随手改，改了以前的分数就没法比了。
- **每个音色都有 `notes.md`。** 没有记录，下次就不知道这一句是怎么选出来的、当初为什么不用另外几句。
- **只在本机自用。** 带这些音色的成品不对外发布。游戏台词是有版权的文本，只留在本机文件里，不贴进对话。

`notes.md` 照这个写，一项一两行：

```markdown
# <音色名>

- 来源：谁给的，什么素材，多长，什么语言，在 data 的哪里
- 候选：怎么切的，切出几句，剔掉了哪些、为什么
- 天花板：这批素材真人自己和自己的中位数和四分位
- 试克隆：日期，测试句的语言，前几名的相似度和语速（全表在 trials\scores.tsv）
- 选定：哪一句，为什么是它
- 听后：你听了之后说的话，照原样记
```

## 这把尺

**相似度**用 IndexTTS 自带的 CAM++ 声纹模型算，1 是完全一致，0 是毫不相干。参照是这个音色的 `voiceprint.npy`。2026-10-04 用咲来量出的刻度：

| 比的是什么 | 相似度 |
|---|---|
| 同一段音频，wav 对 mp3 | 0.98 |
| 她自己的真人台词 | 中位数 0.81，四分位 0.75 到 0.85 |
| 克隆的日语句子，参考句是游戏里的一句原声 | 0.80 到 0.84 |
| 克隆的日语句子，参考句是视频里切出来拼的 | 0.77 到 0.88，但语速慢四成 |
| 同一部游戏里另一位主角的真人台词 | 中位数 0.66，四分位 0.61 到 0.71 |
| 不相干的说话人（IndexTTS 自带的示例音色） | 中位数 0.26，最高 0.45 |

克隆的句子落在真人台词的中位数上，就是这把尺上的满分：真人自己也只有 0.81。别人报的 0.99 以上不是这把尺，在这把尺上只有同一段音频才到 0.98。

用现在这组固定测试句（日语）量，咲来的 12 个候选在 0.77 到 0.81 之间，现用的那一句 0.81；结灯在 0.79 到 0.87 之间，现用的 0.87；诗梦在 0.78 到 0.89 之间，现用的 0.89。新音色拿自己的天花板比，不和别人的数比：素材不同，天花板不同。

**语速**是样句的时长除以基准时长，三句取平均。基准记在 `sentences.json` 每句的 `seconds` 里（去掉首尾静音）：日语是咲来 12 个候选读这一句的时长的中位数，英语是现用的咲来各读一遍的时长，只量过一遍，不如日语的准。1.0 是和咲来平常一样快。同一个人换一句参考句，语速就能差出不少：咲来的 12 个候选在 0.82 到 1.15 之间。同一个参考句把同一句话读两遍，时长也能差一成半。所以语速只用来抓明显的：1.2 以上算偏慢，0.1 以内的差别不算数。

## 素材从哪来：三个例子

**本机的游戏（咲来、结灯、诗梦都是这么来的）。** 游戏里的语音一句台词一个文件，没有背景音乐，是最好的素材。CatSystem2 引擎的游戏（《甜蜜女友2+》）语音按角色分包（`pcm_XX.int`）。`tts pick` 把第 2、3 步一起做了：给包里每一句算声纹，存下中心，再导出 12 句平稳连贯的台词当候选。

```powershell
# 导出台词：日文、中文、每句对应的语音文件名
.\tts dialogue "E:\Game\yx\甜蜜女友\TIANMINY2+" --out voices\咲来\data\game-script
# 存声纹，导出候选到 voices\咲来\candidates（台词在 candidates\台词.txt）
.\tts pick "E:\Game\yx\甜蜜女友\TIANMINY2+\pcm_DD.int" --out voices\咲来 --dialogue voices\咲来\data\game-script\lines.tsv
# 想把整个语音包解出来：一句一个 .ogg，文件名和台词表里的语音名一致
.\tts unpack "E:\Game\yx\甜蜜女友\TIANMINY2+\pcm_DD.int" --out voices\咲来\data\game-voice
```

《甜蜜女友2+》里 `pcm_DD.int` 是咲来（用户听过确认），共 7015 句、9.6 小时；`pcm_AA.int` 是结灯，3900 句、5.4 小时。哪个包是哪个角色，看台词表 `lines.tsv` 里的说话人就知道；语音文件名的前两个字母就是包名。

`pick` 默认只要句中停顿不超过 12% 的句子。说话慢、停顿多的角色按这个门槛可能一句也挑不出来（结灯就是：够长又连贯的句子全在成人场景里），这时加 `--pause 0.2` 放宽。更好的办法是换一种量法，加 `--gap 0.3`：只要求最长的一处停顿不超过 0.3 秒。它按每句话自己的响度来量，录得轻的包也量得准；挑出来的是一口气说下来的句子，克隆出来才顺。

`pick` 的来源也可以是一个文件夹，里面一句台词一个音频文件。网上整理好的分角色语音包（比如 AI Hobbyist 资源库的，解开是一堆 wav 加同名的 `.lab` 台词文本）就这么用。守岸人试过这种包（后来没用上，包也删了）：

```powershell
.\tts pick voices\守岸人\data\游戏语音 --out voices\守岸人 --gap 0.3 --count 10
```

《甜蜜女友3》换了引擎（Artemis），所有角色的语音在同一个包 `Amakano3.pfs.000` 里，按角色代号分目录，要用 `--folder` 指出来。代号和角色的对应同样看台词表：`shi` 是诗梦，`kan` 叶梦，`let` 蕾蒂，`say` 纱由美，`tou` 冬桦。

```powershell
.\tts dialogue "E:\Game\yx\甜蜜女友\3" --out voices\柳木诗梦\data\game-script
.\tts pick "E:\Game\yx\甜蜜女友\3\Amakano3.pfs.000" --folder sound/vo/shi --out voices\柳木诗梦 --dialogue voices\柳木诗梦\data\game-script\lines.tsv
.\tts unpack "E:\Game\yx\甜蜜女友\3\Amakano3.pfs.000" --folder sound/vo/shi --out voices\柳木诗梦\data\game-voice
```

游戏里的语音不用解出来存一份：`tts pick` 直接从游戏包里读，每句的声纹缓存在 `candidates\lines.npz`。所以这三个音色的 `data\` 里只留了台词表（`game-script\`：`lines.tsv` 总表和 `scenes\` 下一个场景一个 txt，日文中文逐句对齐；结灯和咲来共用咲来那份）。2026-10-05 用户让清理目录时，把早先解出来的台词（`game-voice\`）和咲来的旧素材都删了。前提是游戏不卸载；游戏要是卸了，这三个音色就没法重新挑句子，只剩现有的候选。

这是游戏素材的特例。别的来源（下载的、用户给的）没有第二份，原件要留在 `data\` 里。

**B 站的视频。** `tts harvest` 的来源可以直接写 BV 号，音轨先下载到 `data\`，再照常切：

```powershell
.\tts harvest BV1Wr1rBvEct --out voices\<名字>
```

实况视频里大部分时间垫着背景音乐，8 分钟只切出 8 段共 22.7 秒，其中 4 段后来用声纹核对并不是她。这条路素材少、不干净，克隆出来语速慢，只在没有别的素材时用。

**游戏 wiki 上逐句的角色语音（做过泥岩的中文音色，分数不低，但用户听了说不好听，删了）。** 手游的角色语音，wiki 上通常能逐句下载，一句一个文件，没有背景音乐。《明日方舟》在 PRTS 的"<干员名>/语音记录"页，每种语言 38 句上下，长的交谈句有十几到三十几秒，一套总共六七分钟。素材比游戏包少得多，天花板估得粗，但挑一句参考句够用。下载前要用户同意，下到 `data\` 之后照常 `tts harvest`。几点经验：

- 有的角色有两套录音。泥岩默认那套是戴着头盔的，加了闷声效果，要用"摘下头盔时"那套。拿不准就各下一句比一下频谱。
- 这类录音很干净，但句间的呼吸声会让 `harvest` 默认的门槛把整句判成"背景不安静"，加 `--bed -50`。
- 参考句的语言和配音的语言不同也能用，但相似度会低一截：泥岩的中文参考句读中文是 0.88，读日语是 0.83。
- 《鸣潮》的官方 wiki 库街区（wiki.kurobbs.com）每个角色页有"角色语音"，是 48kHz 24bit 的无损 WAV，其中"个性语音"三十来条，够做参考句。音频地址要在页面上点播放才出现，用浏览器把地址读出来再下载。爱弥斯是这么做的。
- B 站上"某角色纯干声"一类的视频能用 `tts harvest <BV号>` 直接取，但质量没保证：爱弥斯那个视频做过降噪或人声分离，又是有损压缩，克隆出来用户听着杂音很多。有官方录音就用官方的，视频只当退路。
- 分数高不等于用户觉得像、觉得好听。泥岩读中文到了 0.88，音高和频谱也和参考句对得上，用户一听还是说不像。素材只有几分钟时，声纹就是拿这几分钟自己算的，分数只说明"像这套录音"。这种音色做完要尽早让用户听，别拿分数下结论。

## 工具

都经根目录的 `tts.cmd` 调用，每个脚本开头有用法。

| 命令 | 做什么 |
|---|---|
| `harvest` | 把录音、视频、B 站音轨切成一句一句的候选 |
| `pick` | 从游戏的角色语音包里存声纹、挑候选 |
| `similar` | 量相似度；`--save` 存声纹 |
| `voice` | 把短片段拼成一条候选 |
| `trial` | 试克隆：每个候选读同一组测试句，出分数表 |
| `dialogue` `unpack` | 导出游戏台词；解游戏语音包（`kif.py` 读 CatSystem2 的 `.int`，`pfs.py` 读 Artemis 的 `.pfs`） |
