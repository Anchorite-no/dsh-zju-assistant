# 自带技能

这里每个文件夹是应用自带的一个技能：替学生把一件要跨几个系统、分几步做的事从头办到尾，最后交给他一样东西（一份选课方案、一份复习计划、一页这周的安排、交上去的作业）。插件页「技能」一组、模型的技能目录和输入框的 `/` 菜单里各有一项。

技能不是命令清单。单个命令怎么用、参数和结果是什么，在 `../zju/references/` 等各 core 的参考文档里，技能不重复；技能写的是这件事怎么办成：先看这个人是什么情况，按他的情况走哪条路，每一步拿到的东西怎么交给下一步，哪里要停下来问他，办完以后接上提醒、备忘录和档案。

## 一个技能的样子

```
course-selection/          文件夹名就是技能名：英文短名，小写字母、数字和短横线
  SKILL.md                 正文：触发说明、总流程、分支
  references/*.md          细的规则、判断表、各系统的坑；正文用相对链接指过来，按需读
  templates/*.md           交付物的格式
```

文件名一律用英文（安装程序写不了名字带中文的文件）。正文里链到别的 core 的参考文档用相对路径，如 `../../zju/references/zdbk-selection.md`。

`SKILL.md` 开头是属性区：

```yaml
---
name: course-selection      # 和文件夹同名
title: 选课                  # 页面上的名字，12 个字以内
description: 一两句话：替用户办成什么；用户会怎么说（「帮我选课」「这门课选哪个老师」）；什么时候不用它
---
```

正文从 `# 大标题` 开始，接一段话说清这个技能办成什么、交付什么，然后是下面六节，标题一字不差（`ui/profile/flows.test.mjs` 核对）：

### `## 什么时候用`

用户会说的话，和容易混的情况：只问一个数（某位老师的评分、某门课的考试时间）直接用工具，不启动整个技能；几个技能挨着的（考前复习要不要先做课后总结）说清先后。

### `## 开始前`

先读这个人的情况，并写明读到的东西怎么改变后面的走法。这是个性化的地方，不能只写「读一下档案」。

- `campus_profile_read`：基础信息（年级、学院、专业）和记忆（每门课的「学过」「还不熟」、「讲解偏好」、「目标与打算」、「个人背景」）。
- `campus_context_read`：校园档案里这门课对应的教学班、平台入口（学在浙大、智云、学习通、PTA）、课程群、事项。只用已确认的关联，未确认的群不当本班的消息。
- `campus_schedule_read`：哪天有什么课、考试、作业截止和备忘录里写了时间的事。
- `campus_note_read`：用户记过的相关的事。
- `schedule_list`：已经建过的定时任务，避免重复建。

没有档案、没有记忆时照样能做：从各平台现查，最后提一句可以用「初始化」把课程和群建成档案，下次就不用再问。不要因为没档案就停下。

### `## 步骤`

用 `### 1. …` 分步。每一步写：要什么、用哪条命令或工具、拿到的结果交给哪一步、分支（「如果……就……」）。互不依赖的查询一次并发发出去。写操作（提交志愿、交作业、报名）单独成一步，前面写清楚给用户看什么、等他说了什么才做，做完回查。

### `## 交付`

交付物是什么、格式照 `templates/` 里哪一份、存到哪（文件给完整路径，照 `core/AGENT.md` 给链接）、在对话里怎么呈现（先给结论，再给表）。

### `## 做完以后`

把这件事接到别的组件上，每一项都先问用户再做：

- 要提醒的时间点（选课各轮截止、考前几天、作业截止前）：问他要不要建定时任务，同意了用 `schedule_create`，提示词照 `../zju/references/schedule.md` 的写法，到点有结果才 `campus_notify`。
- 要留着的结论（定下的选课方案、复习计划）：问他要不要加到备忘录，同意了用 `campus_note_write`。
- 档案里该更新的（新确认的教学班、群）：用 `campus_context_save` / `campus_context_link`。
- 记忆只写技能里明说要记的那一行（比如讲解做完补「看过的讲解」）。「学过」「还不熟」由对话后的复盘按用户自己说的话整理，技能不替他下结论。

### `## 出错和边界`

各系统失败时怎么说、怎么接着做（登录过期、`TRANSPORT`、没有数据、状态是「未公布」）；不做的事（不押题、不替用户做决定、不到点反复提交）；不放进回答和文件的东西（密码、别人的个人信息）。

## 怎么写才不水

- 写判断，不写流水账。「核对教师、学分、时间」是流水账；「这门课是他培养方案里还差的专业选修，而他记忆里写了『不想早八』，就把一二节的班排到后面，并在表里注明原因」是判断。
- 每个分支都要有出口：查不到、没开放、和课表冲突、样本太少，各自怎么办。
- 写清楚结果怎么衔接：上一步的哪个字段是下一步的哪个参数。
- 命令和参数照参考文档写，写到的每条命令、每个 `--参数` core 里都要真有（`flows.test.mjs` 对着命令树查）。
- 不写个人信息。用户是谁、选了什么课，运行时从档案和记忆里读。

## 使用中的补充

照技能办事时用户纠正出来的一条，对话后的复盘会补在旁边（存在档案目录的 `flow-notes.json`，见 `ui/profile/flow-notes.mjs`），接在正文后面「使用中补充的」一节，这里的文件不在使用中改。正文更新以后，之前的补充标成待核对；整理技能时把还成立的补充写进正文。

## 助手自己写的技能

用户说「把刚才这套存成技能」、或者一件事多步探索才走通以后，助手照 [写技能](skill-writer/SKILL.md) 写，结构和这里一样，用 `campus_skill_save` 存在用户的档案目录 `skills/<名字>/`，不改这里的文件。

## 现有的技能

| 技能 | 办成什么 |
|---|---|
| [选课](course-selection/SKILL.md) | 从培养方案的缺口到选上课：该选什么、比较老师、选课方案、各轮提醒、授权后提交和回查 |
| [考前复习](exam-prep/SKILL.md) | 考试安排、老师划的范围、课件、他还不熟的点、往年经验，排成复习计划并按天提醒 |
| [课程学习](course-study/SKILL.md) | 一次课的字幕和课件整理成总结，不懂的地方接着做讲解，攒几次出阶段回顾（考前复习接着用） |
| [我的一周](my-week/SKILL.md) | 今天、这周的课、作业、考试、通知和群消息排成一页，并一次建好每天和每周的提醒 |
| [交作业](homework-submit/SKILL.md) | 读要求、整理成要交的文件、确认后提交、回查 |
| [写技能](skill-writer/SKILL.md) | 把一次走通的事写成以后能照着做的技能 |

初始化（`../initialize/`）和课程讲解（`../learn/`）是各自 core 的技能，也在「技能」一组里。
