# 存之前的检查

存之前逐条过一遍。前四条不过，campus_skill_save 会直接报错；后面几条它查不出来，要你自己把关。

## 存不进去的

- [ ] `name` 是英文短名（小写字母、数字、短横线），不和自带技能重名。
- [ ] 正文从 `# 大标题` 开始，六节标题一字不差：什么时候用、开始前、步骤、交付、做完以后、出错和边界。
- [ ] 每篇参考文档的名字是英文短名加 `.md`，在正文里用 `[说明](references/文件名.md)` 链到了；正文链到的每一篇都给了。
- [ ] 正文不超过两万字，参考文档不超过 8 篇。

## 查不出来、要自己把关的

- [ ] **说明写得出用户的原话。**`description` 里有三到五种用户会说的话，模型靠它决定要不要加载。
- [ ] **开始前写了怎么改变走法。**不是「读一下档案」，而是「读到什么就怎么走」。没有档案时也写了怎么办。
- [ ] **没有个人信息。**没有学号、姓名、具体的课名、老师、成绩、账号；这些写成运行时读哪里。
- [ ] **命令是这次真跑通的。**照原样抄的成功的那条，具体的值换成了占位；没走过的分支标了「这次没走过」。校园命令照 zju 技能的写法执行，参数以它的参考文档为准。
- [ ] **每个分支有出口。**查不到、没开放、登录过期、结果不确定，各写了怎么办。
- [ ] **写操作单独一步，先给用户确认。**没有写「直接提交」「不用问」。
- [ ] **弯路变成了判断。**对话里走错过的地方，写成了「如果……就……」或「不要……，因为……」。
- [ ] **交付物说清了。**格式、存在哪、对话里怎么呈现。
- [ ] **做完以后接上了别的组件。**提醒、备忘录、档案，每项都是先问用户。
- [ ] **不和已有技能重复。**办同一件事的已有技能，改的是那一个；自带技能里的一步，没有另建。
- [ ] **给用户看过。**名字、什么时候用、各步的标题、带哪几篇参考文档。
