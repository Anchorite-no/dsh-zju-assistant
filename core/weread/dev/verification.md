## 隐藏验证码修复与复验（2026-10-12）

根因已经定位：微信读书首页使用 OverlayScrollbars，并通过 requestIdleCallback 延迟初始化。初始化代码重新 append 页面 body 的子节点，导致我们提前插入的官方验证码 iframe 重载。生命周期记录显示 iframe 的 frameTreeNodeId、routingId、performance.timeOrigin 都变化；新导航由微信读书 Nuxt 脚本发起，而非腾讯拒绝答案。DOM 断点调用栈落在该脚本的 OverlayScrollbars 节点移动逻辑。

正式修复：微信读书桌面 Nuxt 页面先等待根元素的 `data-overlayscrollbars` 初始化标记，再启动官方验证码；文本正文页无需等待。等待上限 10 秒，未就绪返回 verification_page_not_ready，保留原有题目版本和坐标校验。窗口默认隐藏；配置了识别模型时自动验证也隐藏，只有扫码登录或未配置模型时显示窗口。

|---|---|
| 等页面就绪后，全程隐藏完成真实六图验证 | 成功，腾讯返回 0 和有效回执，随后带票据请求文章列表返回 HTTP 200、20 组文章；模型耗时 1.451 秒 |
| 将等待条件接入正式模块后复验 | 成功，真实六图再次取得回执，模型耗时 1.549 秒；3 个窗口始终 isVisible=false，show/showInactive/focus 调用次数为 0 |

诊断脚本仍使用正式浏览器和模块。`hidden-after-page-ready/` 是先行假设验证；`production-fixed/` 没有使用额外等待补丁，只记录正式代码的结果。证据在 `downloads/hidden-verification-20261012/` 对应子目录、`cli-export/` 和 `fix-summary.json`，没有保存验证码票据或 Cookie 值。

范围：这是隐藏 Electron 的六图交互样本，不能推导为真正 Headless 或所有题型均已通过。此次修复后列表请求已被此前验证放行，交互题由官方微信读书组件主动发起，随后带票据检查业务；本轮没有新增自然 -2041 触发后恢复原页的线上样本。其余多题型的跨进程合成测试仍用可见窗口；尝试将整个合成用例直接改为隐藏时超时，尚不能作为隐藏多题型证据，已保留原测试方式。
