# 开发原则

本文件用于用户明确要求维护本项目的开发任务。普通校园查询与操作只按 SKILL.md 调用业务命令，不应转成读源码、改脚本的开发任务。

## 面向 Flash 模型的任务接口

用户于 2026-09-23 明确要求：最终调用者是推理能力有限、应尽可能少思考的 Flash 模型。CLI 必须承担可确定的业务流程，不能把内部步骤和执行策略交给模型选择。此要求适用于全部模块。

- 模型只负责理解用户目标、传入必要业务信息、转述最终结果；认证、发现、匹配、分页、轮询、计算、提交、回查、去重、恢复和停止由代码完成。
- 一个完整用户任务优先一次 CLI 调用。不得要求模型读源码、猜响应字段、搬运内部 ID、生成胶水脚本或选择中间执行模式。
- 公开参数必须对应用户真实需要表达的目标或约束。不得仅因底层存在某能力，就公开一个参数或命令；内部函数可组合，不等于必须让模型组合。
- 结果应直接表达任务状态、完成事项、未完成原因及必要证据；不要求模型解释平台协议或多个互相冲突的状态字段。
- SKILL 的日常说明必须短而直接，协议细节留给开发参考。文档说明不能代替代码封装。
- 2026-09-24 补充：信息完整后的普通判断由模型完成，不为每种问法新增计算接口。例如复用完整课表接口，补齐官方起止时间并缓存，让 AI 判断“下一节课”；不另造 next-class 脚本。
- 2026-10-06 用户明确：命令改名、搬迁或删除时直接删掉旧入口，不做迁移提示这类 fallback。开新会话就能读到新说明；兼容入口做多了项目会变复杂。
- 2026-10-07 用户明确：命令按对象分组成树，写成「模块 对象 动作」（`sztz activity signup`、`xuezai homework submit`）；成对的做与取消合成一个命令，取消加 `--cancel`，不另开一个命令；不留只有动词、看不出对象的命令名（如单独的 `cancel`）。只有一个动作的对象直接作叶子（`sztz credits`、`zdbk timetable`）。
- 文件按实际职责组织；不为分层而拆文件，也不靠机械合成大文件宣称流程完整。优先复用用户已经验证可用的脚本逻辑，逐项核对迁移差异。
- 验收使用最终 Flash 模型和真实用户任务，核对调用次数、端到端耗时与业务结果。类型检查和模拟通过不能代替真实业务验收。

## 当前确认边界

修改工具本身不代表授权真实选退课、交作业或发布内容；这些写流程用隔离数据验收。范围和证据见提交记录，历史授权不扩展到后续无关任务。

## 外部信息路由

需要外部资料时，优先专用工具；其次按用途分别使用 zhihu 的 search zhihu / search global；不足再用 Exa、Jina、Tavily；只有需要 JavaScript、认证、交互或视觉检查时使用浏览器。业务现场不能靠临时网上搜索弥补脚本缺失的确定性逻辑。
