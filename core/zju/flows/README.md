# 工作流

这里保存定制化、步骤复杂、模型只看命令说明难以推断的工作流：步骤顺序、决策点和各步之间的数据衔接。单个命令的参数、结果和限制见对应 reference，不在这里重复。

这里只放开发整理过的工作流。助手在使用中探索出来的做法不写进这个目录，用 campus_skill_save 存成技能，放在用户的档案目录 `skills/` 里，插件页的「技能」一组能看、能删。开发定期去看用户反馈上来的技能：稳定的整理成这里的工作流，能确定的做成命令。

照这里的工作流办事时学到、正文里没有的一条（比如被用户纠正了的一步），由应用在对话结束后补在旁边：存在用户的档案目录，加载 zju 技能时拼在正文末尾的「工作流的补充」里（见应用的 `ui/profile/flow-notes.mjs`）。这里的文件照旧不在使用中改。正文更新以后，之前的补充会标成待核对；整理工作流时把还成立的补充写进正文。

每个工作流在应用里也是一个自带的技能：插件页「技能」一组列着它（带「自带」的标记，只能看），技能目录和输入框的 `/` 菜单里也有，名字就是文件名。所以文件名用英文短名（小写字母、数字、短横线），文件开头的属性区写 `title`（给人看的名字）和 `description`（什么时候用，写出用户会说的词）；没有 `description` 的文件只当 zju 里的一篇文档，不单独列出来。写法可以当助手自己存技能时的样子参照：适用的问题、按顺序的步骤、每一步用哪条命令、哪里要先问用户。
