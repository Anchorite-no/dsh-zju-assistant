## 已定的决策

1. **通知能力独立成 `notice` 模块**，教务网 `zdbk` 只保留课表、考试、成绩、培养方案、选课和会话。现在挂在 `zdbk` 里的通知代码（`lib/zdbk/xtgl.ts` 整个、`lib/zdbk/bksy.ts` 整个）搬到 `lib/notice/`。**`zdbk notice` 直接删除，不留迁移提示**（用户 2026-10-06 明确：以后都不做迁移提示这类 fallback，开新会话就读到新说明，fallback 多了项目变复杂）。
2. **按平台家族写适配器，站点和栏目只当数据。** 一个 webplus 适配器通吃部处官网；教务网、竞赛系统各一个适配器。加来源等于加一行数据。
3. **综合服务网不包含教务网**（实测教务网最近 33 条只有 2 条在综合服务网出现），三类来源都要接：综合服务网（部处发全校）、教务网（本科生院和院系教学运行）、部处官网独有栏目。
4. **默认来源集**：教务网两类通知、本科生院学籍管理和实践交流、学工部最新通知/重要通知/评奖评优/学生资助/公示公告、**综合服务网"教育教学"和"重点提示"两栏**。综合服务网"即时更新"栏不进默认集：9-30 当天 16 条里 9 条是科研院转发的基金指南、3 条是招聘和经费认领，和学生有关的只有 2 条，按"最新 10 条"合并会把教务网通知整页挤掉。"即时更新"只在 `--source 综合服务网` 指名时和 `notice new` 增量扫描时读。
5. **增量入口独立成子命令 `notice new`**：只回上次之后新出现的条目的标题、日期、来源和链接，不带正文，由模型挑出相关的再 `notice view`。它会改本地已读记录，和无状态的 `notice list` 分开。某个来源读取失败时不推进该来源的记录；整次运行的记录在结果组装完之后一次写入。
6. **比赛前（10-21）只做教务网加 webplus 四个站**：综合服务网、本科生院、学工部、信息技术中心（需统一认证的 webplus，顺带解决 `flows/itc-notice.md` 的问题）。研工部、研究生院、图书馆是同一个适配器，只是加数据行，一并写进来源表但不进默认集。计财处、研究生教务、就业、竞赛列表这些各要一个适配器的放到比赛之后。

## 目录与职责

```text
lib/notice/
  module.json       name=notice，auth=cas（信息中心栏目需要），network=campus，writes=false，requires core/profile/zjuam/webvpn/zdbk
  sources.ts        来源表，见下
  types.ts          Notice / NoticeDetail / Source / Column
  article.ts        通用正文解析（原 parseNoticeDetail）：教务网详情页、webplus、学院 CMS 的正文容器、附件、内嵌 PDF
  adapters/
    webplus.ts      网站群通用：列表解析、翻页、遇 CAS 自动 loginService
    zdbk.ts         教务网：列表、标题截断与完整标题缓存、详情；用 zdbk/client.ts 的 Zdbk 客户端
    kyjs.ts         竞赛管理系统正文（原 bksy.ts 的 kyjsNotice）
  index.ts          按来源表取列表 → 合并 → 去重 → 按日期排序 → 取 limit 条正文；view；new 与已读记录
  cli.ts            notice list / view / new / sources
references/notice.md     CLI 用法
lib/notice/README.md     协议：webplus 规律、各站列表项模板、CAS 栏目处理、已读记录文件格式
```

依赖方向：notice → zdbk/client（借教务网会话，`doc` 读教务网附件已是这种用法）、webvpn、zjuam。zdbk 不依赖 notice。只查某个来源时不打开其他来源的会话；一个来源失败，其余照常返回，结果标 partial 并写明哪个来源没读到。

不搬进来的：`lab notices`（实验平台公告）、`tyys venue notice`（预约须知）、`cc98 account notifications`（论坛消息）。notice 只管各单位公开发布的通知公告；个人收件类（学在课程公告、邮箱、OA 待办）以后单独考虑。

## webplus 适配器要点

- 列表 `/<栏目>/list.htm`，第 N 页 `list{N}.htm`；页脚 `<em class="all_pages">`、`all_count`、`per_count`。
- 列表项统一规则：一个 `<li>` 里一个指向 `page.htm`（或外链）的 `<a>` 加一个日期；日期可能是 `YYYY-MM-DD`、`YYYY.MM.DD`，或拆成 `news_y` + `news_m` 两段（组织部）。已见 5 种模板，一个解析器处理，不按站写分支。
- 文章 `/YYYY/MMDD/c<栏目>a<文章id>/page.htm`，文章 id 全站群递增。
- 正文 `.wp_articlecontent`，通用正文解析已支持；补 `.art-summary` 的"编辑/来源/时间"。附件 `/_upload/article/files/…`，PDF 可能是 `<div pdfsrc>`。
- CAS：请求结果落在 `zjuam.zju.edu.cn/cas/login?service=…` 时，取 service 交给 `ctx.zjuam.loginService`，同一上下文重取；实测 2.4 s。
- 翻页策略：按时间排列的栏目读到页内最旧日期早于所需范围或凑够条数为止；bksy 两栏固定读全部页。
- 去重：综合服务网、部处站、教务网会重复发同一条。标题归一化（去【】、去前缀和标点）后短的整段出现在长的里、且日期相差不超过 14 天，视为一条，保留来源表里排在前面的。

## 命令面

- `zju notice list`：默认来源集最新 10 条全文；`--source 学工部、图书馆`（顿号分隔；可写来源名或栏目名，如 `评奖评优`；`全部` 表示全部来源）、`--keyword`（多个说法顿号分隔）、`--since`/`--until`、`--limit`。
- `zju notice view --url 链接` 或 `--title 标题`；多个用竖线分隔，结果总是列表。
- `zju notice new`：增量来源里上次之后新出现的条目，只有标题、日期、来源、链接。第一次运行给最近 7 天。
- `zju notice sources`：已接来源与栏目、是否默认、是否在增量里、上次检查时间。
- `zdbk notice list/view`：删除。
